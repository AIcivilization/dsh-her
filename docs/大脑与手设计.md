# 设计：她是入口，循环是她的内在驱动（2026-11-14 讨论完；实施见 [实施计划](实施计划.md)）

> 用户的想法：独立出来的是**身体**，会说会听；**大脑是外接的**，现在接 dsh，以后能接 Claude、Codex 和别的，大脑同时也是干活的**手**。我们的产品是**和人打交道的界面**：人对着她说，**她把事情分配下去做，聊天也是一件事**。
>
> 她的行为方式照 [agent-autoloop](https://github.com/KKKKhazix/agent-autoloop)：自己接活、自己跟进到底，平时不烦你，拿不准才来找你拍板。**这是让身体活过来的内在驱动。**
>
> 这一份接在 [独立安装包设计](独立安装包设计.md) 后面：那一份讲怎么把她装到别人的电脑上，这一份讲装上以后她怎么活着、怎么干活。

## 已经定了的

1. **她是入口**（2026-11-14）。人对着她说话或打字，她背后用外接的大脑想事情、干活，再用她的声音告诉人。
2. **她的行为方式是 agent-autoloop 的那个循环**（2026-11-14，用户："这个才是我们的行为方式，就是让我们的身体活过来的内在驱动"）。事件进来 → 按规则派活 → 干完一轮就退出 → 拿不准才问你 → 你答了接着干。
3. **分配不交给某一家的会话，由一个不挑大脑的内核来管**（2026-11-14）。原来打算自己写这个内核；现在 agent-autoloop 的内核正好就是它，而且是 MIT 许可，可以直接拿。怎么拿见下面第 5 条。
4. **dsh 之外先接 Claude Code，Codex 第二个**（2026-11-14）。学完以后这条的意思变窄了：**干活的手** agent-autoloop 已经把 Claude Code、Codex、dsh、ACP（Gemini CLI、OpenCode）、ZCode 和"任何能打印最后一条回复的命令"都接好了，不用我们一个个接；这条只管**前台聊天用的大脑**（要一个字一个字流出来给她念的那个）先接谁。
5. **内核两样都支持：用户自己装了 agent-autoloop 就连上去，没有就用我们自带的一份**（2026-11-14）。
   - 她启动时先看这台电脑上有没有在跑的中台（它的数据文件夹 `~/.agent-autoloop/` 和健康检查接口）。有，就作为通道和来源连进去，用户原来的规则、Agent、别的通道都照旧。没有，就起我们自带的那一份，数据放在真人桌宠自己的数据文件夹里。
   - 两种情况她用的是**同一份代码**：都是按它的 HTTP 协议连进去，这正是它"一切都连进来"的设计。
   - 自带的那份钉住一个发布版本，连同它的版权声明和 MIT 许可全文一起放进程序；升级前跑它的一致性检查。
   - 用户以后自己装了 agent-autoloop：她发现以后问一次"要不要改连你自己装的那份"，自带的那份停掉，不同时跑两份。
   理由：一台电脑上只能跑一份中台，已经装了的人我们不能再起一份去抢活；而普通人不会自己去装，所以必须自带。
   已经核实：我们身体用的 Electron 44.7.0 自带 Node 24.21.0，`node:sqlite` 能用，够它的要求（Node 24 以上）。
6. **任务台是桌面上的一个小窗**（2026-11-14）。
   - 平时收起来：她身边只露一个小标记，比如"2 件在做 · 1 件等你"；什么事都没有时标记也不显示（注意力最贵）。
   - 点开是小窗，从上到下：**等你的**（卡片全文、选项、推荐项，能点、能写一句别的想法）；**在做的**（哪条规则、交给了谁、跑了多久，能停掉）；**约好的**（到点要复查的事和时间）；**最近做完的**（一句话结论，点开看来龙去脉）；最下面一行是今天和最近 7 天的轮数、Token、费用。
   - 它是读中台全局状态的一个客户端（`/v1/state` 加日志流），自己不存业务状态；回答、结案、停掉用的就是"本人"那几个请求。
   - 卡片两条路都能答：听她说完开口答，或者在小窗里点。只有第一次回答算数（这是中台保证的）。
   - 托盘菜单里只放一行"打开任务台"和等你的卡片数。
   - 手机和网页里的任务台以后再加：数据是同一份，加一页就行。
   理由：卡片不能只靠她念，长一点的内容要有地方看全文；回答和停掉是常用动作，要有地方点。

**补充（2026-11-25）**：Codex 不做前台大脑（不能逐字回来，命令行工具关不掉），留给"手"那一层。前台大脑是 dsh、Claude Code、OpenAI 兼容的 key。

## 1. agent-autoloop 是什么

看了全部代码结构，读了协议、状态机、插件说明、安全边界和配置手册。

- **一个很轻的自动化中台**。TypeScript，要 Node 24 以上，**运行时零依赖**（数据存在 Node 自带的 SQLite 里）。MIT 许可。2026-11-03 建的仓库，5000 多个星，每天在更新。
- **一个内核，四个方向的插件**：

  | 方向 | 管什么 | 自带的 |
  |---|---|---|
  | 事件（来源） | 怎么发现新活 | 定时、GitHub / GitLab、HTTP 接口、轮询脚本 |
  | Agent | 谁来干活 | Claude Code、Codex、ACP、**DeepSeek Harness（dsh）**、ZCode、通用命令（Cursor 等一行接入） |
  | 通道 | 去哪找你拍板 | 桌面通知、飞书、钉钉 / 企微 / Slack / Discord |
  | 交付 | 把上线流水线也做成插件 | PR：审查 → 等 CI → 合并 → 等部署 → 核对线上 |

- **没有界面**。它明说："想要一个页面或大屏，用这几个请求自己做，它和命令行是同等的客户端。"
- **内核不主动连任何东西**。来源、干活的、通道都是自己连进来，走同一份 HTTP + JSON 协议；内核不保管任何凭据。一台电脑上用时，一条命令把它们跑在一个进程里。
- 用的是用户电脑上已经装好、登录好的命令行工具，不碰它们的登录。

## 2. 它的行为方式

### 六个词

| 词 | 是什么 |
|---|---|
| **事件** | 发生了一件事。时间到了是事件，你点了卡片也是事件 |
| **规则** | 什么事件，交给哪个 Agent，在哪个文件夹，照哪份手册，什么时候告诉你 |
| **事项** | 同一条规则下同一个对象的事。卡片、到期复查、会话都挂在事项上 |
| **一轮** | 一次执行：领一批事件，交一份回执，然后结束。一轮会结束，事项会继续 |
| **回执** | Agent 的最后一条消息。它想让中台做的事全写在这里，一次生效 |
| **卡片** | 给你看的东西。带选项的是提问，你选了就是一条新事件；不带选项的是通知 |

### 六条原则

1. **注意力最贵。** 默认安静。没事不说话，能自己做的自己做完，只有规则写明要先问的事、确实要本人解除的阻塞才打断你。
2. **一切都是事件。** 外面的系统、时间、到期的复查、你的决定，走同一条路。
3. **一切都连进来。** 内核不往外发请求。凭据留在用它的地方，出事的范围也留在那里。
4. **Agent 就是一个进程。** 给它提示词，它打印最后一条消息。不需要 SDK。
5. **一轮不等人。** 要问你就结束这一轮；你答了再接着原来的会话干。等你的时候不占进程、不花 Token，重启也不丢。
6. **规则才是指令。** 事件决定不了交给谁、在哪个文件夹、给什么权限，这些只由你本机的规则定。别人写的话不进提示词，只放进标明"是资料"的文件。

### 回执里的五个动作

一轮结束时，Agent 在最后一条消息里可以写：

| 动作 | 意思 |
|---|---|
| `ask` | 问你一件事，带选项和推荐项，还给"接着干的自己"留一句话 |
| `notice` | 告诉你一声。可以标成"仅告知"，不要你点 |
| `resolve` | 把一张已经不用决定的卡片结掉，写明在哪核实的 |
| `later` | 约个时间再醒来复查（"半小时后看看部署好了没"） |
| `events` | 发出新的事件，再派给别的 Agent |

### 四个保险

- **挂起零消耗**：等你拍板时进程直接退出，状态在数据库里。你三天不回，这三天不花一分钱。
- **事件溯源**：所有状态从一条只追加的日志算出来。任何一轮为什么跑、结果是什么，一条命令查清。
- **指令和资料分开**：思路和 SQL 参数化一样，外面来的文字进不了提示词。
- **跳数熔断**：Agent 发的事件再派给 Agent，层数累加，超过 8 层就不再派，发卡片告诉你。

另外还有：同一件事排队时又来的消息合并成一轮；没跑成自动重试，最多 10 次；回执写错了只让它重写最后一段，不重做业务；能暂停、恢复、补跑、停掉；每轮记 Token 和费用。

## 3. 为什么说它是让身体活过来的内在驱动

现在的她只在两种时候动：你跟她说话，或者"先开口"的计时器到了。她没有自己的事。

有了这个循环，她有了一直在往前走的**事项**：

| 循环里发生的 | 她身上看得到的 |
|---|---|
| 来了一件事，派下去了 | 她说一句"接下了"（或者不说，看规则的 `tell`） |
| 有手在干活 | 她在"干活"的样子（编排里多一种时机：有事在做） |
| 一轮干完，没什么要你管的 | 她什么都不说。**注意力最贵** |
| 来了一张提问卡片 | 她在合适的时候开口问你，头顶气泡里是选项；你说"第二个"或点一下 |
| 来了一张通知 | 她告诉你一声 |
| `later` 到点了 | 她自己醒来去复查，不用你记着 |
| 全都安静 | 她待机、发呆、按编排过她的日子 |

所以"先开口"从此有了内容：她开口是因为**真的有事**（做完了、要你定、到点了），不是为了找话说。什么时候可以打扰你，还用现在那套规则（安静时段、专注、你在不在）；卡片可以等，循环不等人，这两件事正好对得上。

## 4. 她在循环里的位置

```
                    事件                    领活
   来源 ───────────────▶   中台内核   ◀─────────── 接单程序 ── 手
   定时 / GitHub /         （agent-autoloop）       Claude Code / Codex / dsh / …
   她听到你交代的事           ▲   │
                        回答 │   │ 卡片
                            │   ▼
                    ┌───────────────────────┐
                    │ 她（我们做的）           │
                    │  通道：把卡片说给你听、   │ ◀──▶ 你
                    │       把你的回答交回去   │
                    │  来源：你交代的事变成事件 │
                    │  任务台：看全局、停掉     │
                    │  前台：陪你聊天          │
                    └───────────────────────┘
```

她是围着内核的四样东西：

1. **通道**。这是最贴合的一处：它自带的桌面通道只会弹一个系统通知，**答不了**（要你去敲命令行）。她正好补上这个缺：一个会开口问、能听你回答、能点的通道。接口只有四个调用：领卡片、报告送到了、报告没送到、转交回答。
2. **来源**。你对她说"把昨天的笔记整理一下"，前台听懂这是一件要干的事，就往中台发一条事件。照哪条规则、交给谁、在哪个文件夹，由规则定，不由这句话定（原则 6）。
3. **任务台**。就是它说的"用这几个请求自己做一个页面"：读全局状态、回答、结案、停掉。
4. **前台**。带着她人设的聊天会话。见下一节。

原来定的几条原则都还成立，而且和它的原则对得上：**她是谁放在我们这边**（它也说"中台不替 Agent 记事"）；**她只分配不动手**（前台没有动文件的工具，只能发事件）；**说和做分开**（回执第一行就是"一句话结论"，她念这一句）。

## 5. 聊天：走不了它的"一轮"，留在我们这边

"聊天也是一件事"在道理上成立，但实际上聊天不能交给内核去派：

- 它只取 Agent 的**最后一条消息**，没有流式。她说话要一个字一个字地出来、断句、能被你打断。
- 每一轮要启动一次命令行工具，几秒钟。聊天等不起。

所以聊天由前台自己做：一个一直开着的、流式的会话（现在 dsh 里的她就是这样）。前台多一个工具"交下去"，用它往中台发事件；中台那边的结果以卡片的形式回来，由她说给你听。聊天这件事可以在任务台上记一行，但不经过内核。

## 6. 哪些能直接拿，哪些要自己做

MIT 许可允许拷贝、修改、连同我们的产品一起分发，条件是保留它的版权声明和许可全文。

| | 内容 |
|---|---|
| **直接拿来用** | 内核（事件、规则、事项、轮次、卡片、定时、复查、重试、熔断、日志）；接单程序；Claude Code、Codex、dsh、ACP、通用命令这几个 Agent 插件；协议和它的一致性检查；现成的场景模板（早报、盯 Issue、网站巡检、收件箱分诊……） |
| **照着它的接口自己写** | 她这个**通道**（说、听、气泡、点）；她这个**来源**（你交代的事）；**任务台**；把循环的状态接到**编排**上（有事在做、有卡片等你） |
| **还是我们自己的** | 身体、嘴和耳朵、人设、记忆、前台的流式聊天 |
| **它没有、我们也先不做** | 干活过程的实时进度（它只有"领走了、做完了"和最后一句结论；过程的输出留在本机文件里 14 天） |

被它替掉的、不用自己写的：排队和同时几只手的上限、重试、停止、"要批准时怎么办"、花费统计、每件事的来龙去脉。上一版打算自己设计的"接头分三级"也不用了：它的做法更简单，**干到要拍板的地方就结束这一轮、发卡片，你答了接着原来的会话干**，手在干活时不需要有人守着批准。

## 7. 要注意的

1. **账号的用法**。它自己写了：后台高频自动跑时，各家更建议用 API key，个人订阅的额度主要是给人守着用的。我们做成给普通人的产品，这一条要在设置里说清楚。
2. **"先问我"挡不住一切**。`askFirst`（删数据、花钱、对外发消息……）只是写进提示词的要求，Agent 不照做，中台拦不住；真正挡得住的是权限档（只读 / 只改工作文件夹 / 全部）和 Agent 自己的沙箱。默认用"只改工作文件夹"。
3. **它才出来十一天，每天在变**。要钉住一个发布版本用，升级前跑它的一致性检查。
4. **它要 Node 24 以上**，用了 Node 自带的 SQLite。已核实我们的 Electron 44.7.0 自带 Node 24.21.0，够用；以后升级 Electron 或它时要再看一眼。另外它的源码是直接跑 TypeScript 的，放进我们的程序要先打成一个包（我们本来就用 esbuild 打包）。
5. **一台电脑上只能跑一份中台**。所以定了"有就连，没有才用自带的"（见"已经定了的" 5）。
6. **你交代的话是"资料"不是"指令"**。规则里要先有"在哪个文件夹、交给谁"，她才能把事派过去。所以要有一步"告诉她你有哪几个干活的地方"，每个地方是一条规则。

## 8. 路线，和还没定的

路线（[独立安装包设计](独立安装包设计.md) 的八件决定都不变）：

| 阶段 | 是什么 |
|---|---|
| 一 | **桌宠版**：没接大脑时的她 |
| 二 | **接大脑**：前台能聊天，发声、听、记忆 |
| 三 | **接循环**：她当通道和来源，任务台；手用 agent-autoloop 接好的那些 |
| 四 | **她自己的日子**：定时的事、复查、场景模板；循环的状态接到编排上 |

剩下的几件小事用户让我定（2026-11-14："这些小事你决定就好"），记在 [实施计划](实施计划.md) 开头：干活的地方由她问一次记下、设置里能改，权限默认只改那个文件夹；dsh 里的她也接循环，排在真人桌宠之后；名字不动。

按顺序的十七步见 [实施计划](实施计划.md)。
