# 设计：她是入口，大脑和手是外接的（讨论稿，2026-11-14，还没写代码）

> 用户的想法：独立出来的是**身体**，会说会听；**大脑是外接的**，现在接 dsh，以后能接 Claude、Codex。大脑同时也是**手**，能干活。我们的产品是**和人打交道的界面**：人对着她说，**她把事情分配下去做，聊天也是一件事**。再把 [agent-loop](https://github.com/Saik0s/agent-loop) 的做法综合进来。
>
> 这一份接在 [独立安装包设计](独立安装包设计.md) 后面：那一份讲怎么把她装到别人的电脑上，这一份讲装上以后她怎么想事情、怎么干活。

## 已经定了的

1. **她是入口**（2026-11-14）。人对着她说话或打字，她背后用外接的大脑想事情、干活，再用她的声音告诉人。不是"人在终端里用 Claude Code，她在旁边报告"那种（那种以后可以顺手加，不是主线）。

## 1. agent-loop 是什么，能拿什么

看了仓库（2025 年 7 月以后没更新，19 个星）：

- **它不是一个程序，是一套给 Claude Code 用的配置**：一个 `CLAUDE.md`、二十来个斜杠命令（`/plan`、`/build`、`/test`、`/orchestrate`……）、几篇说明，加一个 `install.sh` 把它们拷进 `~/.claude/`。
- **它讲的是一种做法**：一个"协调者"只管分配，不自己写代码；具体的事交给各个"专家"（架构、实现、测试、调试、研究、评审……）；每件交下去的事都按一个固定的"任务单"写清楚。
- 说明里列了十一个专家，但**仓库里没有这些专家的定义文件**（没有 `agents` 文件夹），只有命令。
- **没有许可证**。没写许可就是保留所有权利，它的文件我们不能拷进产品里。
- **它的 `install.sh` 会覆盖** `~/.claude/` 里的 `CLAUDE.md`、`settings.json`、`commands`、`docs`。我们绝不能替用户跑这个。

所以"接过来"的意思是：

| | 做法 |
|---|---|
| **拿它的做法**（做法不受版权限制，我们自己写） | 她只分配、不动手；任务单；工种；同时做几件有上限；大的结果写成文件、只回一个位置 |
| **和它兼容**（不拷它的文件） | 她分配给 Claude Code 时，用的是用户自己电脑上的 Claude Code。用户自己装了 agent-loop（或别的命令包），那些命令在干活的那一头自然就能用，她可以直接把事交给 `/build`、`/plan` |
| **不拿** | 它的文件、它的安装脚本、它 `CLAUDE.md` 里作者个人的规矩（比如"不许跑测试"） |

这和我们对设计的态度一样（见 [产品定义](产品定义.md)）：我们做引擎，别人的东西各自独立，按约定接进来。

## 2. 综合以后的样子

```
        人
        │ 说话、打字、点一下
┌───────▼────────────────────────────────────────────┐
│ 她（我们的产品：和人打交道的界面）                      │
│                                                    │
│  身体      样子、编排、气泡、触摸、住在桌面上            │
│  嘴和耳朵   发声、听、断句、口型、打断                   │
│  她是谁    人设、记忆                                │
│  前台      听懂人要什么 → 自己答，或者写任务单交下去     │
│  任务台    每件事一行：谁在做、做到哪、要不要你批准、结果  │
└───────┬──────────────────┬─────────────────────────┘
        │ 前台用的大脑       │ 任务单 ↓   进度、要批准、结果 ↑
        ▼                  ▼
   外接的大脑          外接的手（可以同时好几只）
   dsh / Claude /      dsh / Claude Code / Codex
   Codex / 一个 key    各自在一个文件夹里干活
```

五条原则：

1. **她是谁放在我们这边，不放在大脑里。** 人设、记忆、声音、样子跟着她走。换一个大脑，她还是她，还记得你。人设通过提示词交给大脑；记忆通过"记住、想起、忘掉"几个工具交给大脑。
2. **什么都是"一件事"，聊天也是。** 人说的每句话，前台先判断：这是聊天（她自己马上答），还是要干的活（写任务单，交下去）。两种都记在任务台上，只是聊天这件事由她自己做、当场做完。
3. **她只分配，不动手。**（agent-loop 的"协调者不写代码"。）前台这个会话**没有**读写文件、跑命令的工具，只有：交一件事下去、看任务台、给某件事补一句话、停掉某件事、记忆、做动作。这同时是一道保险：带着人设和你闲聊的那个会话，碰不到你的文件。
4. **说和做分开。** 手干活时吐出的代码、命令输出，她不念。她只说人话：接下了（"好，我让 Codex 去改"）、要你批准（"它要删这个文件，行吗"）、做完了（"改好了，测试过了 12 个，有一个要你看看"）。过程在任务台里看。
5. **动手前由她来问你。** 手要改文件、跑命令而需要批准时，变成她开口问，你说"好"或点一下。什么时候可以打扰你，用现在"先开口"的那套规则（安静时段、专注、你在不在）。

## 3. 前台：她怎么分配

前台是一个带着她人设的会话，接一个外接的大脑。它比现在 dsh 里的她多四个工具：

| 工具 | 干什么 |
|---|---|
| 交下去 | 写一张任务单，选交给谁（哪只手）、在哪个文件夹里做 |
| 看任务台 | 现在有哪些事、各自什么状态 |
| 补一句 | 给一件正在做的事加一句话（"顺便把说明也改了"） |
| 停掉 | 停一件事 |

**干活不卡住聊天。** 每只手是单独的一个会话、单独的进程。交下去以后前台马上回到你这边，你可以接着聊、再交别的事。手那边有了动静（要批准、做完、失败），变成一条消息回到前台，她挑合适的时候告诉你。

**前台的大脑和手可以不是同一个。** 比如前台用便宜、反应快的模型（聊天要快），手用 Claude Code 或 Codex（干活要强）。也可以全用同一个。

## 4. 任务单

她交事情下去时写的那张单子，我们自己定的（参考了 agent-loop 的九段模板，砍成普通人也看得懂的五段）：

```
标题      一句话
目标      要做成什么
背景      为什么要做；人原话是怎么说的
范围      要做的 / 不要碰的
怎么算做完  几条能检查的标准
```

- 小事（"把这个文件名改一下"）她直接交下去。
- 大事她先把任务单给你看一眼："我打算这样交代下去，行吗"，你点头再交。多大算大，由一个设置定（默认：估计要改多个文件，或者要跑很久的）。
- 手做完以后回一段短的结果，她照着说；长的东西（报告、改动清单）写成文件，任务台里点开看。

## 5. 手：能接什么

一只手 = 一个能干活的 agent。我们为每一种写一个接头（适配器），接口都一样：

| 接口要的 | dsh | Claude Code（Agent SDK / `claude -p` 流式模式） | Codex（`codex exec --json` / 它的 SDK） |
|---|---|---|---|
| 交一件事进去 | 有 | 有 | 有 |
| 实时拿到进度（在说什么、在用什么工具） | 有 | 有 | 有 |
| 停掉 | 有 | 有 | 有，要实测 |
| 要批准时先来问 | 有 | 有（权限回调） | 比较弱，要实测 |
| 中途补一句 | 有 | 有 | 要实测 |
| 接着上次的会话做 | 有 | 有 | 有 |

- **用的都是用户电脑上已经装好、登录好的命令行**，我们不碰任何 key，也不替用户装它们。没装的那一种，在设置里显示"这台电脑上没有"。
- **在哪个文件夹里干活由人定**：第一次交事情时她问"在哪个文件夹里做"，记住常用的几个。手只在那个文件夹里动。
- **同时最多几只手**有上限（默认 3），多的排队。
- **工种**（agent-loop 的"专家"）：一个工种 = 用哪只手 + 一段开头的交代。自带几个最普通的（写代码、查资料、检查）；用户自己的 Claude Code 里有什么命令和子 agent，照样能用。第一版不做工种的编辑界面。

前台的大脑用的是同一套接头，只是不给它动文件的权限、换上她的人设。所以"接一个大脑"和"接一只手"是同一份代码的两种用法。另外前台还可以接"一个 OpenAI 兼容的 key"这种最简单的大脑（只能聊，不能当手）。

## 6. 这对已经定的事有什么影响

[独立安装包设计](独立安装包设计.md) 的八件决定都不变。变的是路线：

| 阶段 | 是什么 | 原来怎么写的 |
|---|---|---|
| 一 | **桌宠版**：没接大脑时的她。住在桌面上、按编排来、碰她出台词 | 不变 |
| 二 | **接大脑**：前台能聊天。发声、听、记忆、先开口。大脑可以是 dsh、Claude、Codex，或一个 key | 原来是"聊天版 = 对方填 DeepSeek key" |
| 三 | **接手**：任务台、交事情下去、她来问批准、报结果 | 新加的 |

实施顺序里要改的：

- 安装包计划的第 2 步（把不依赖 dsh 的东西挪出来）要做大：声音、听、记忆、断句、先开口也挪出来，都算身体这边的。
- 定一个"大脑接口"（上面第 5 节那张表），把 `src/dsh/her-session.ts` 整理成它的**第一个实现**。dsh 版的她行为不变，但从此 dsh 只是"大脑和手的一种"。
- dsh 里的她和真人桌宠，以后只差两点：引擎住在谁的进程里；接的是哪个大脑、哪些手。

## 7. 还没定、要问用户的

1. **分配由谁来管**：我们的引擎管任务台（上面写的就是这种：聊天不被卡住，前台和手可以不同）；还是交给一个 Claude Code 会话自己去分子任务（省事，但只有 Claude 能用，干活时她没法聊）。
2. **第一个接哪个大脑**：dsh（已经有）之外，先做 Claude 还是 Codex。
3. **任务台长什么样**：桌面上一个小窗；还是只在托盘菜单里列几行；手机和网页里要不要也能看。
4. **批准的尺度**：每一步都问、只问危险的（删东西、联网、推送）、还是按文件夹设"这里随便做"。
5. **dsh 里的她要不要也有任务台**：还是只有真人桌宠有。
6. **真人桌宠这个名字**：加了"分配事情"以后，她不只是桌宠了，名字还合不合适。
