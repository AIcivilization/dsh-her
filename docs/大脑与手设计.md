# 设计：她是入口，大脑和手是外接的（讨论稿，2026-11-14，还没写代码）

> 用户的想法：独立出来的是**身体**，会说会听；**大脑是外接的**，现在接 dsh，以后能接 Claude、Codex 和别的。大脑同时也是**手**，能干活。我们的产品是**和人打交道的界面**：人对着她说，**她把事情分配下去做，聊天也是一件事**。[agent-loop](https://github.com/Saik0s/agent-loop) 的机制**完整学过来**，用在我们接的任何一种大模型工具上。
>
> 这一份接在 [独立安装包设计](独立安装包设计.md) 后面：那一份讲怎么把她装到别人的电脑上，这一份讲装上以后她怎么想事情、怎么干活。

## 已经定了的

1. **她是入口**（2026-11-14）。人对着她说话或打字，她背后用外接的大脑想事情、干活，再用她的声音告诉人。不是"人在终端里用 Claude Code，她在旁边报告"那种（那种以后可以顺手加，不是主线）。
2. **分配由我们的引擎来管**（2026-11-14）。任务台、排队、交给谁、什么时候算做完，都在引擎里；不是交给某一个 Claude Code 会话自己去分子任务。
   理由：聊天不被干活卡住；前台和手可以用不同的模型（聊天要快，干活要强）；dsh、Claude、Codex 都能用，不绑在一家上。
3. **agent-loop 的机制完整学过来，写成我们自己的、不挑大脑的版本**（2026-11-14）。
   - 学的是机制，文字和文件都自己写：它没有许可证，文件不能拷；它的安装脚本会覆盖用户 `~/.claude/` 里的设置，不能替用户跑。
   - 它的机制全写在 Claude Code 的配置文件里，所以只有 Claude Code 能用。我们把机制放进**引擎**：该硬性保证的由引擎保证，该照着做的写进前台的提示词，该告诉手的写进任务单。手只要能"收一段话、干活、回一段话"就能用上全套。
   - 用户自己的 Claude Code 里装了 agent-loop 或别的命令包，照样能用，我们不拦也不依赖。
4. **dsh 之外，先接 Claude Code，Codex 第二个**（2026-11-14）。
   理由：Claude Code 的接口最全（逐步批准、中途补一句、接着上次做、报花费都有），能把第三级接头一次做全，接口也就定准了；Codex 在"要批准时先来问"这一项上要实测，放第二个，用它来检验接口是不是真的不挑大脑。
   做法：用用户电脑上已经装好、登录好的 Claude Code（不带界面的流式模式），我们不碰 key。前台和手都先用它跑通。

## 1. agent-loop 的完整机制

通读了仓库里全部 36 个文件。它是一套给 Claude Code 用的配置：一个 `CLAUDE.md`、23 个斜杠命令、7 篇说明、两份设置、一个安装脚本。说明里列了十一个"专家"，但仓库里没有它们的定义文件，只有命令。把它的机制拆开，一共九样：

| # | 机制 | 它是怎么做的 |
|---|---|---|
| 1 | **协调者只分配，不动手** | 协调者读懂命令 → 选一个专家 → 把背景、目标、怎么算成功交代清楚 → 盯着做 → 对照原来的要求检查结果。它自己从不写代码 |
| 2 | **专家（工种）** | 架构、实现、难题、调试、规划、查资料、评审、定范围、安全、测试。每件交下去的事都要写明用哪个专家、哪个命令、为什么 |
| 3 | **任务单** | 固定九段：目标；背景（为什么）；范围（做什么、不碰什么）；验收标准（一条条能检查的）；交付物（文件、文档、测试）；实施计划；参考资料；专家和命令；给专家的叮嘱。每张单有唯一的编号 |
| 4 | **分配规则** | 最多同时 10 个，多的自动排队；规划和查资料的事**同时交给 3 个，比一比挑最好的**；大的产出写成文件，只回一个位置 |
| 5 | **做法（命令）** | 每个命令是一份固定骨架的做法：背景、任务、一步步的过程、例子、注意。常见的步骤是：问清楚 → **先找现成的例子和背景**（"没找到例子不许动手"反复出现）→ 计划 → **先说清怎么算成功** → 交下去 → 检查（跑测试）→ **自查三问**（要求都满足了吗、测试够吗、合不合项目的习惯）→ 按固定格式汇报（问题、轻重、怎么改） |
| 6 | **思考的档位** | 动手前先想：想一想、多想想、使劲想，三档 |
| 7 | **多个视角** | 评审按架构、实现、测试、安全、运维五个视角各过一遍；"会诊"是 4–6 个专家做几轮，每一轮都能看到别人上一轮写的，主持人每轮汇总、指出没讲到的、不许重复，最后出一份总的 |
| 8 | **怎么开一只手** | 不带界面地启动；流式拿进度；记下会话编号以后接着做；**一定设轮数上限**防止跑飞和乱花钱；能看花了多少钱；换系统提示词；允许和禁止哪些工具；权限三档（只出计划、只自动改文件、全自动）；同时做几份时各在各的文件夹或 git 分支里，互不干扰；设超时 |
| 9 | **借别人的长处，和项目的规矩** | 读超大的代码库交给上下文大的模型（Gemini）；要看最新文档用查文档的工具；任务清单有依赖、优先级、子任务、"下一件该做什么"（TaskMaster）。规矩：没让开分支不许开、用户没测过不许提交和推送、改原来的文件不另起一份、每条命令都记下来。它还用钩子让电脑的朗读功能把通知念出来 |

它平时的用法是一条链：出计划 → 写规格 → 实现 → 测试 → 分析 → 更新文档。

**有两样我们不学**：它默认把权限设成"全自动、什么都不问"（我们反过来，默认要问）；它 `CLAUDE.md` 里作者个人的习惯（比如"不许跑测试"）。

## 2. 综合以后的样子

```
        人
        │ 说话、打字、点一下
┌───────▼────────────────────────────────────────────┐
│ 她（我们的产品：和人打交道的界面）                      │
│                                                    │
│  身体      样子、编排、气泡、触摸、住在桌面上            │
│  嘴和耳朵   发声、听、断句、口型、打断                   │
│  她是谁    人设、记忆                                │
│  前台      听懂人要什么 → 自己答，或者选做法、写任务单   │
│  任务台    每件事一行：谁在做、做到哪、要不要你批准、结果  │
│  做法和工种  这类事怎么做、交给哪种手                    │
└───────┬──────────────────┬─────────────────────────┘
        │ 前台用的大脑       │ 任务单 ↓   进度、要批准、结果 ↑
        ▼                  ▼
   外接的大脑          外接的手（可以同时好几只）
   dsh / Claude /      dsh / Claude Code / Codex / 别的
   Codex / 一个 key    各自在一个文件夹里干活
```

五条原则：

1. **她是谁放在我们这边，不放在大脑里。** 人设、记忆、声音、样子跟着她走。换一个大脑，她还是她，还记得你。人设通过提示词交给大脑；记忆通过"记住、想起、忘掉"几个工具交给大脑。
2. **什么都是"一件事"，聊天也是。** 人说的每句话，前台先判断：这是聊天（她自己马上答），还是要干的活（选做法、写任务单，交下去）。两种都记在任务台上，只是聊天这件事由她自己做、当场做完。
3. **她只分配，不动手。** 前台这个会话**没有**读写文件、跑命令的工具。这同时是一道保险：带着人设和你闲聊的那个会话，碰不到你的文件。
4. **说和做分开。** 手干活时吐出的代码、命令输出，她不念。她只说人话：接下了、要你批准、做完了。过程在任务台里看。（agent-loop 用电脑的朗读功能念通知；在我们这里，念的人就是她。）
5. **动手前由她来问你。** 手要改文件、跑命令而需要批准时，变成她开口问，你说"好"或点一下。什么时候可以打扰你，用现在"先开口"的那套规则（安静时段、专注、你在不在）。

## 3. 九样机制，在我们这里各放在哪

要让任何一种手都能用，机制不能写在某一家的配置里。每一样拆成三处：**引擎硬性保证**的（不管接的是什么模型都成立）、**前台照着做**的（写在前台的提示词里）、**写进任务单告诉手**的（一段普通的话，谁都看得懂）。

| 机制 | 引擎硬性保证 | 前台照着做 | 写进任务单 |
|---|---|---|---|
| 1 只分配不动手 | 前台没有动文件的工具；一件事没经过检查不算"做完" | 读懂、选人、交代、对照要求检查 | |
| 2 工种 | 工种卡：一段交代 + 默认用哪只手 + 权限档 + 思考档 | 每件事选一个工种，写一句为什么 | 工种的那段交代放在最前面 |
| 3 任务单 | 编号唯一；九段缺了必填的不许交 | 写任务单；大事先给人看 | 九段全文 |
| 4 分配规则 | 同时几只手的上限、排队；"三选一"时同时开三份；大产出放进这件事的文件夹 | 比较三份，挑一份，说为什么 | "长的东西写成文件，回我位置" |
| 5 做法 | 做法文件（我们自己的格式）；步骤的先后 | 按做法一步步来：问清楚、说清怎么算成功、自查三问、按格式汇报 | "先找现成的例子再动手"；汇报的格式 |
| 6 思考档位 | 把三档换成每只手自己的开关（各家的思考力度设置） | 定这件事用哪一档 | 没有开关的手，在话里写"动手前先想清楚" |
| 7 多个视角 | 几轮、每轮把别人上一轮的结果发给每一位 | 当主持人：汇总、指出没讲到的、不许重复 | 各自的视角 |
| 8 怎么开一只手 | 接头（第 6 节）：不带界面、流式、接着做、轮数和时间上限、花费、权限档、各做各的文件夹 | | |
| 9 长处和规矩 | 每只手登记"擅长什么"；提交、推送、删除一定要问；每条命令都记进这件事的记录 | 按长处挑手 | 这个文件夹的规矩 |

接了三种以上的大脑以后，第 4 和第 7 样比原版更有用：**"三选一"和"会诊"可以真的交给三个不同的模型**（比如 Claude、Codex、DeepSeek 各出一份），而不是同一个模型问三遍。

## 4. 前台、任务台、任务单

### 前台

前台是一个带着她人设的会话，接一个外接的大脑。它的工具只有：

| 工具 | 干什么 |
|---|---|
| 交下去 | 交一张任务单：用哪个做法、哪个工种、哪只手、在哪个文件夹里做 |
| 看任务台 | 现在有哪些事、各自什么状态、下一件该做什么 |
| 补一句 | 给一件正在做的事加一句话（"顺便把说明也改了"） |
| 停掉 | 停一件事 |
| 记住、想起、忘掉 | 她的记忆 |
| 做动作 | 身体上的表现 |

**干活不卡住聊天。** 每只手是单独的一个会话、单独的进程。交下去以后前台马上回到你这边。手那边有了动静（要批准、做完、失败），变成一条消息回到前台，她挑合适的时候告诉你。

**前台的大脑和手可以不是同一个。** 比如前台用反应快的模型，手用 Claude Code 或 Codex。

### 任务台

每件事一行（学了 agent-loop 借用的 TaskMaster 的结构）：

- 编号、标题、是哪一种（聊天 / 干活）、做法、工种、哪只手、哪个文件夹；
- 状态：排队、在做、等你批准、等检查、做完、搁着、取消、失败；
- 先后：这件事要等哪几件做完；轻重（高、中、低）；
- 子事情：一件大事拆成几件小的，编号是 `5.1`、`5.2`；
- 结果：一段短的；长的产出、全部记录（手跑过的每条命令）在 `<数据文件夹>/tasks/<编号>/` 里；
- 花了多久、多少轮、多少钱（手报得出来的话）。

### 任务单

交给手的是九段全文（和 agent-loop 的结构一样，文字我们自己写）：

```
编号和标题
1 目标          一句话，要做成什么
2 背景          为什么要做；人的原话
3 范围          要做的 / 不要碰的
4 验收标准       一条条能检查的
5 交付物         改了或新建的文件、文档、测试
6 实施计划       （可以没有）
7 参考           （可以没有）现成的例子、文档
8 工种和做法     用哪个、为什么
9 叮嘱           这个文件夹的规矩；长的东西写成文件；汇报的格式
```

给人看的只有四行：**标题、目标、范围、怎么算做完**。小事她直接交下去；大事先给你看这四行，"我打算这样交代下去，行吗"，你点头再交。多大算大由一个设置定。

## 5. 做法和工种

**做法**是"这类事怎么做"的一份文件，我们自己的格式（什么时候用、要做成什么、一步步怎么做、哪一步交给哪个工种、怎么检查、怎么汇报）。引擎自带一套，对应 agent-loop 的全部命令：

| 类别 | 自带的做法 |
|---|---|
| 想清楚 | 把一句含糊的话问清楚；写规格（谁、要什么、为了什么，加验收标准）；出两三个方案比较并推荐一个；出计划（改哪些文件、先后、风险、怎么测）；先了解这个项目 |
| 做 | 实现（计划 → 测试计划 → 说清怎么算成功 → 找例子 → 实现 → 测试 → 跑测试 → 自查）；先写测试再实现；搭一个新项目；升级依赖 |
| 查 | 分析（几个视角各看一遍，汇总成按轻重排的清单）；调试（重现 → 看日志 → 顺着走 → 找到根源 → 修）；连问五个为什么；评审；补测试 |
| 多人 | 三选一；会诊（几位、几轮、互相看、主持人汇总） |
| 收尾 | 提交前检查并提交；更新文档；画结构图 |
| 不是写代码的 | 聊天（她自己做）；查资料并注明出处；写一段东西；整理文件 |
| 加做法 | 照着格式写一个新做法；你说"以后这种事都这样做"，她可以替你写一个 |

做法可以放在两处：整台电脑通用的，和只在某个文件夹里用的。

**工种**是一张卡：名字、一段交代、默认用哪只手、权限档、思考档。自带十个，和 agent-loop 的专家一一对应：规划、架构、实现、难题、调试、查资料、评审、定范围、安全、测试。

第一版不做做法和工种的编辑界面，它们是数据文件夹里的文本文件，会的人可以自己改。

## 6. 手：能接什么

一只手 = 一个能干活的大模型工具。每一种写一个**接头**。不是每种工具都一样能干，所以接头分三级，每只手说明自己是哪一级，她照着用：

| 级别 | 这只手能做到 | 她怎么用它 |
|---|---|---|
| 一 | 收一段话，干完回一段话（任何带"不带界面运行"的命令行工具） | 只交不用批准的事：只读的分析、查资料；或者在一份单独的拷贝里做，做完你看过再合进来 |
| 二 | 加上：实时进度、能停、轮数和时间上限、接着上次做 | 能交一般的活；权限事先定死（只出计划 / 只自动改文件） |
| 三 | 加上：每一步要批准时先来问、中途补一句、报花费 | 全部用法，包括她替它开口问你 |

| | dsh | Claude Code | Codex | 别的命令行工具（Gemini 等） |
|---|---|---|---|---|
| 预计能到的级别 | 三（已经有） | 三 | 二到三，要实测 | 一到二，要实测 |

- **用的都是用户电脑上已经装好、登录好的工具**，我们不碰任何 key，也不替用户装。没装的那一种，在设置里显示"这台电脑上没有"。
- **在哪个文件夹里干活由人定**：第一次交事情时她问，记住常用的几个。手只在那个文件夹里动。同时做几份（三选一）时，每份在各自的拷贝或 git 工作区里，互不干扰。
- **上限都有默认值**：同时最多 3 只手（agent-loop 是 10，普通人的电脑和钱包受不了，可以调）、每件事的轮数、时间。到了上限就停下来问你。
- **权限默认要问**，和 agent-loop 相反。提交、推送、删除，任何档位下都要问。

前台的大脑用的是同一套接头，只是不给它动文件的权限、换上她的人设。所以"接一个大脑"和"接一只手"是同一份代码的两种用法。另外前台还可以接"一个 OpenAI 兼容的 key"这种最简单的大脑（只能聊，不能当手）。

## 7. 这对已经定的事有什么影响

[独立安装包设计](独立安装包设计.md) 的八件决定都不变。变的是路线：

| 阶段 | 是什么 | 原来怎么写的 |
|---|---|---|
| 一 | **桌宠版**：没接大脑时的她。住在桌面上、按编排来、碰她出台词 | 不变 |
| 二 | **接大脑**：前台能聊天。发声、听、记忆、先开口。大脑可以是 dsh、Claude、Codex，或一个 key | 原来是"聊天版 = 对方填 DeepSeek key" |
| 三 | **接手**：任务台、任务单、做法和工种、交事情下去、她来问批准、报结果 | 新加的 |
| 四 | **多只手一起**：三选一、会诊、几个视角的评审 | 新加的 |

实施顺序里要改的：

- 安装包计划的第 2 步（把不依赖 dsh 的东西挪出来）要做大：声音、听、记忆、断句、先开口也挪出来，都算身体这边的。
- 定"接头"的接口（第 6 节），把 `src/dsh/her-session.ts` 整理成它的**第一个实现**。dsh 版的她行为不变，但从此 dsh 只是"大脑和手的一种"。
- dsh 里的她和真人桌宠，以后只差两点：引擎住在谁的进程里；接的是哪个大脑、哪些手。

## 8. 还没定、要问用户的
