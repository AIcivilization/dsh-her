# M1 记录：大脑与身体打通（文字）

> 2026-10-28，Apple M1 Pro，macOS 27.2，DSH 0.2.1-rc.3（`her-dev` 测试 profile），身体 Electron 44.7。

## 做了什么

**大脑（插件）**
- `src/server/brain-server.ts`：本机 WebSocket 服务。
  - 首选端口 38100，被占用就往后找，最后让系统随便分配。
  - 令牌存在 `<home>/token`（600），只在 `hello` 消息里出示，不进 URL。
  - 发现文件 `<home>/brain.json`（600），dsh 退出时删掉。
  - 心跳：45 秒没动静就断开。
  - 协议版本和令牌对不上时，回 `reject` 并说明原因。
- `src/dsh/plugin.ts`：
  - 她会话里的每一条回复，不管是谁发起的（身体输入框、dsh 网页、`/her`），都按句以 `speak.begin / seg / end` 推给身体。
  - 身体发来的文字交给她的会话。她正在说时你又打字，就先打断她（`speak.cancel`）再交给她。
  - 没有身体连着、也没有身体在运行时，3 秒后自动拉起 `body/`。
- `src/dsh/her-session.ts`：回复编号改成"编号@轮次.步骤"。**dsh 的编号会跨轮重复**，不改的话身体会把不同回复混在一起。

**身体**
- `body/main/brain-link.ts`：
  - 先用插件传来的地址，失败后读发现文件。
  - 断线退避 1→30 秒；`brain.json` 一被改写就立即重连。
  - 运行时写 `<home>/body.json` 记下自己的进程号，插件就不会再拉起第二个。
- 只允许运行一个实例。
- 全局快捷键 **⌃⌥空格 / Ctrl+Alt+空格** 打开输入框；在壁纸模式下按，她会先切到最上层。原定的 Alt+空格在 Windows 上是系统窗口菜单，所以换掉了。
- 字幕气泡：按句显示，按朗读时长停留后淡出；被打断时加"——"；"思考中"显示省略号动画；最上面的旧句子渐隐滚出。
- 片段池按状态选片段（`talk` / `think` 等，外形包里没有的状态用 `idle` 代替）。
- **省电**：2 分钟没有互动就进入休息：片段播完停在最后一帧，每 20–40 秒播一段；任何互动立即恢复。

## 验收

| 项 | 结果 |
|---|---|
| dsh 启动后自动拉起身体并连上 | ✅ 约 3 秒 |
| 身体先开、dsh 后开 | ✅ dsh 写出 `brain.json` 后 **约 250 ms** 连上，没有拉起第二个身体 |
| 身体输入框说话 → 她在气泡里回答 | ✅ 首句约 2 秒（模型时间） |
| 在 dsh 网页里用 `/her` 说话 → 桌面上回答 | ✅ |
| dsh 退出 | ✅ `brain.json` 删除，身体进入"在等 dsh"（菜单栏显示"她·睡"） |
| 断线时打字 | ✅ 气泡提示"我现在连不上 dsh，等它开起来再说吧" |
| dsh 重启后 | ✅ 不到 1 秒重连；**旧回复不重播**；接着聊正常 |
| 打字打断她 | ⚠️ 模型生成很快（一个 14 句的故事 4.3 秒生成完），生成结束后大脑已认为她说完了，所以只是新回复替换气泡，没有发 `speak.cancel`。真正的"说到哪被打断"要等 M2 有了音频：由身体按播放进度上报 `interrupt` |
| 休息模式 CPU | ✅ 平均 **2.2%**（峰值 17.7%，是间歇播放的那一段） |

## 休息模式 CPU

最后一次互动 2 分钟后开始测，测 120 秒，单核口径：

| 状态 | 平均 CPU |
|---|---|
| 持续播放（M0） | 约 17–18% |
| **休息：停在一帧上，每 20–40 秒播一段** | **2.2%** |
| 暂停（M0） | 0.4% |

符合 M0 的估计（2–4%）。

## 留给 M2 的事

- 身体在播放/朗读期间被打断时，上报 `interrupt{uid, seq, playedMs}`；大脑在下一轮附上"她说到哪被打断了"。
- dsh 网页在插件驱动她的会话时偶尔不刷新显示（M0 发现），本轮没有再复现，继续观察。
