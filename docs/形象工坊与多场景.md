## 1. 用户怎么用（从拿到产品开始）

```
装好 → 向导 → 第 3 步"选一个她"
          ├─ 样板间（已经在本机，点一下就用）
          ├─ 基于样板间改（复制一份成自己的项目，进工坊改衣服、发型、场景）
          └─ 自己做一个（进形象工坊，从空白开始）
```

- 第一次打开，**不做任何事也能用**：直接用样板间。
- 想要自己的，**从样板间改起最容易**：角色卡、场景、提示词都是现成的，只改想改的。
- 完全从零做，工坊一步一步带着走，**最少 1 张图 + 3 段视频**就能看到她动起来，以后再一点点补。

## 2. 概念

```
她（角色）
├─ 人设、称呼、声音、记忆           ← 大脑这边，已有
└─ 形象
   ├─ 角色卡        她长什么样：性别、年龄段、肤色、发型、发色、体型、服装、配饰、画风
   ├─ 参考图        纯色背景、全身、正面站立。她的"身份证"，所有图和视频都以它为准
   ├─ 桌宠          绿幕全身片段，"浮在最上层"时用
   ├─ 场景 × N      每个场景 = 全屏照片 + 人物区 + 一组片段 + 出现条件
   └─ 换装 × N      同一个人的另一身衣服（对应现有的 `锚点@衣服`）
```

- **场景**沿用现在的场景包（全屏照片 + 人物区，`docs/外形包与姿势图.md` §4.5），**一个场景就是现在的一个包**。
- **形象**是新加的一层：把几个场景、桌宠、换装和切换规则放在一起（格式见 §7）。
- 三种窗口模式用到的素材：
  - 浮在最上层：桌宠片段；
  - 住在壁纸里：场景；
  - 普通窗口：场景（按照片比例开窗）。

  样板间三种都要有。用户自己做的，有哪种就能用哪种模式。

## 3. 样板间（唯一的预设）

**目标**：用户打开就觉得"她活着"。所以要比用户自己做的版本丰富得多：多个场景、会换衣服、会进出画面、在不同时间做不同的事。

**草稿**（形象和人设都要你定，§10）：

| 项 | 内容 |
|---|---|
| 人设 | 二十多岁、在家工作的插画师，温柔，会吐槽（和现在测试用的小禾一个方向） |
| 声音 | Edge 晓晓，语速 1.0（以后换成更好的音色） |
| 衣服 | 2 身：家居服（默认）、出门的连衣裙（说"换身衣服""出门啦"时换） |
| 桌宠 | 绿幕全身：待机 ×2、说话 ×3、听、想、开心、害羞、挥手、被戳、犯困，约 12 段；第二身衣服至少待机、说话 3 段 |

**场景**（每个场景约 12 段：待机 ×2、说话 ×3、听、想、开心、害羞、挥手、这个场景特有的动作 1–2 段、进场和出场各 1 段）：

| 场景 | 姿势 | 特有动作 | 什么时候出现（默认） |
|---|---|---|---|
| 窗边 | 站 | 端着咖啡喝一口、看窗外 | 早上 7–10 点 |
| 书桌 | 坐 | 在数位板上画画、伸懒腰 | 白天；你在用电脑时 |
| 沙发 | 坐 | 翻书、打盹 | 傍晚；你很久没动时 |
| 卧室 | 站 | 整理头发、伸懒腰 | 晚上 |
| 床上 | 躺 | 入睡、睡着、被叫醒 | 深夜 0–7 点 |

**规模**：桌宠约 15 段 + 5 个场景 × 约 12 段 ≈ 75 段。场景片段只有人物区那么大，转码后每段约 1MB，整套约 100MB，放进安装包可以接受。

**怎么做出来**：用我们自己的形象工坊（§4）做。工坊能把样板间做出来，就说明普通用户也能用它做出东西。

**要先确认**：样板间里的她必须是 AI 生成的虚构人物，不能像任何真人；用的生成工具要允许商用。

## 4. 形象工坊（自定义）

放在 dsh 的「她」页面：设置 → 形象 →"做一个新形象"或"基于样板间改"。桌面上她右键菜单里的"做场景…"并进来，作为其中一步（2026-11-10：身体的设置窗口去掉了，框人物区只在页面里做）。

### 4.1 五步

| 步 | 做什么 | 程序定的 | 用户定的 |
|---|---|---|---|
| 1. 角色卡 | 描述她 | 字段、选项 | 每一项选什么；也可以上传一张图"看图填写" |
| 2. 参考图 | 生成或上传她的"身份证" | 规格、提示词的规则块 | 选哪张 |
| 3. 场景 | 有哪些场景，每个场景的照片和人物区 | 推荐的场景、按屏幕给出的尺寸、安全区 | 加哪些场景、各自什么时候出现、照片、人物区框在哪 |
| 4. 片段 | 每个场景（和桌宠）要哪些视频 | 必须的 3 段、规则块、负面提示词 | 加哪些推荐段、改动作描述、加自己的段 |
| 5. 收片段 | 导入、检查、修、补 | 检查项、自动修复 | 不合格的要不要重做 |

每一步都能先跳过、以后再回来；工坊里一直显示"这个形象现在能用哪些模式、还缺什么"。

### 4.2 角色卡：选择题，不是填空题

- 每一项给几个带小图的选项，再加一个"自己写"。比如发型：长直发 / 长卷发 / 短发 / 马尾 / 丸子头 / 自己写。
- 年龄段只能选成年（§8）。
- 一边选，旁边一边**拼出"角色描述"这句话**，例如"戴细框眼镜、棕色长卷发、穿棕色吊带和米白短裙、平底鞋的年轻女性"。用户能看到自己的选择变成了什么话，也可以直接改这句话。
- **看图填写**：上传一张现成的图，让 dsh 里能看图的模型把角色卡填好，用户再改。

### 4.3 提示词分三层

| 层 | 内容 | 谁定 | 用在哪 |
|---|---|---|---|
| 规则块 | 固定机位、不切镜、开头结尾回到原姿势、没有文字水印、身体完整在画面内；桌宠加"纯绿背景、没有阴影"；负面提示词 | 程序，按类型和生成工具选 | 每一段 |
| 角色描述 | 上面拼出来的那句话 | 用户（通过角色卡） | 参考图、每个场景的照片、每一段视频 |
| 动作 | 这一段做什么 | 预设，用户可改、可加 | 只有这一段 |

**同一句角色描述贯穿所有图和视频**，再加上参考图，她才不会这一段一个样、那一段一个样。

**场景照片里的她要和参考图一致**：教程里明确要求用生成工具的"参考图 / 保持人物一致"功能，把参考图放进去生成每个场景的照片。这是多场景能不能做成的关键。

### 4.4 生成工具档案

不同工具能力不一样，规则块、输出什么、导入后怎么处理都跟着工具走：

| 工具 | 首尾帧 | 工坊给什么 | 导入后 |
|---|---|---|---|
| MiniMax Code（Hailuo 2.3） | 只有首帧 | 任务文件，用户在 MiniMax Code 里发一句话 | 自动处理成循环 |
| MiniMax H3、百炼首尾帧模型 | 都支持 | 任务文件；百炼有 key 时可以直接调接口（付费，先给出预计费用） | 一般不用处理 |
| 即梦、可灵、豆包（手动） | 看模式 | 每段一个"复制提示词"按钮 + 图文教程（点哪里、选什么比例、时长、分辨率） | 看检查结果 |

**任务文件要写进这次的经验**：统一模型和设置；同时最多 5 个任务；每段一完成就下载；临时文件不放进代码仓库；只做缺的段，已有的不覆盖。

### 4.5 收片段：检查、修、补

在现有的导入检查（`docs/外形包与姿势图.md` §4）上加：

| 检查 | 不合格时 |
|---|---|
| 首帧和参考图 / 场景照片像不像 | 提示"人走样了"，列进重做清单 |
| 尾帧能不能接回首帧 | **自动处理成循环**（正放一遍再倒放一遍，首尾都是原图；这次测试就是这样修的）；以后可以加"在最接近首帧的地方截断 + 短淡化" |
| 分辨率够不够（按用户的屏幕算，§6） | 提示"会被放大 1.5 倍，略糊" |
| 绿幕均不均匀、有没有阴影 | 说明原因，提示词里加强对应的话再重做 |
| 比例、时长、帧率 | 能转码就转码 |

- 修不了的，**一键生成"只重做这几段"的任务文件**或复制清单。
- **重新导入替换同一个形象**，编排和选择都保留，旧版本自动留一份可以退回。不再出现"测试""静止预览"这样一堆重复的外形。
- 报告里不只说"不合格"，要说原因和下一步怎么做。

## 5. 多场景：每个场景什么时候出现

### 5.1 选哪个场景（优先级从高到低）

| 优先级 | 条件 | 例子 |
|---|---|---|
| 1 | 你说了 | "去卧室吧""换身衣服"，马上去 |
| 2 | 特殊日子 | 生日、节日（她的记忆里有这件事）：换一身衣服或去特别的场景 |
| 3 | 你在不在 | 你一直在用电脑 → 书桌陪你工作；很久没动 → 沙发打盹；你回来 → 起身打招呼 |
| 4 | 时间段 | 早上窗边、白天书桌、傍晚沙发、晚上卧室、深夜床上 |
| 5 | 都不满足 | 回到默认场景 |

- "你在不在"**只用系统的空闲时间**（多久没碰键盘鼠标），不看你在用哪个程序、打了什么字。
- 夜里该睡的时候，她"睡"的状态和"床上"场景配合：先去床上，再入睡。

### 5.2 怎么切才不烦

- **至少停 20 分钟**再自动切（你说的除外）。
- **正在说话、在听你说话时不切**，等这轮结束。
- **可以锁定**：设置里或者跟她说"就待在这吧"。锁定后只有你说了才换。
- **切换要有过程**：有出场、进场片段就播（她走出画面 → 照片淡换 → 她走进来）；没有就整体淡出淡入，0.8 秒，不硬切。
- 切过去后她可以顺口说一句（"我去窗边坐会儿"），由大脑决定说不说，不是每次都说。

### 5.3 设置页：场景表

| 场景 | 开 | 什么时候 | |
|---|---|---|---|
| 窗边 | ✓ | 7:00–10:00 | 现在去这里 |
| 书桌 | ✓ | 白天 · 你在用电脑时 | 现在去这里 |
| … | | | |

顶上一个总开关"自动换场景"（默认开）和"锁定在当前场景"。默认值由形象自带，用户不改也能用。

## 6. 按用户的屏幕给提示

身体是桌面程序，能知道每块屏的像素、比例、缩放倍数，连上大脑时报给它。工坊和导入检查都**按这个人的屏幕说具体的数**。

### 6.1 给出的提示

| 素材 | 提示 | 例子 |
|---|---|---|
| 场景照片 | 比例和屏幕一样，宽至少等于屏幕像素宽 | "你的屏幕是 3024×1964（16:10），照片请做到这么大" |
| 场景片段 | 人物区在屏幕上的实际像素多大，片段就要多大 | "人物区在你屏幕上约 1060×1890，请选 1080P" |
| 桌宠片段 | 她在屏幕上的高度 × 缩放倍数 | 一般 720×1280 就够；她放得很大或 4K 屏时建议 1080×1920 |
| 比例不对 | 预览裁掉的部分，并给出解决办法 | "照片是 16:10，屏幕是 21:9，上下会被裁掉约 1/3 →用即梦、豆包的'扩图'把照片扩到 21:9" |

### 6.2 不切到人

常见屏幕：MacBook 16:10，普通显示器 16:9，带鱼屏 21:9，部分笔记本 3:2。照片铺满屏幕时多出的部分会被裁掉，**人物区被裁就会切到她**。

现在就有这个问题：卧室照片是 16:10，人物区占满整个高度；放到 16:9 的屏幕上，上下各裁掉约 5%，她的头顶和鞋会被切掉。

做法：
1. **铺满时以人物区为准**：现在是居中裁；改成在能盖满屏幕的前提下，挪动照片让人物区完整可见，并尽量居中。
2. **框人物区时画安全区**：做场景时把 16:9、16:10、21:9 下能看到的范围画成线，人物区超出某个比例的范围就提醒。
3. **一个场景可以有几张不同比例的照片**（同一个人物区位置），身体选和屏幕比例最接近的一张。样板间每个场景带 16:10、16:9、21:9 三张（用扩图做），任何屏幕都不切人、不放大太多。
4. **多块屏**：让用户选她住在哪一块，提示按那一块来算。

## 7. 文件格式（已实现）

**形象**：`<home>/looks/<id>/look.json`。场景和桌宠都是**已经导入的包**，按包 id 引用；包本身还是现在的格式。

```json
{
  "format": "dsh-her-look@1",
  "id": "showroom",
  "name": "样板间",
  "desk": "showroom-desk",
  "scenes": [
    { "id": "window", "name": "窗边", "pack": "showroom-window", "when": { "hours": "7-10" } },
    { "id": "desk", "name": "书桌", "pack": "showroom-desk-scene", "when": { "hours": "10-18", "user": "active" } },
    { "id": "sofa", "name": "沙发", "pack": "showroom-sofa", "when": { "user": "idle" } },
    { "id": "bedroom", "name": "卧室", "pack": "showroom-bedroom", "when": { "hours": "21-24" } },
    { "id": "bed", "name": "床上", "pack": "showroom-bed", "when": { "hours": "0-7" } }
  ],
  "default": "bedroom",
  "minStayMinutes": 20
}
```

- `hours`："7-10" 表示 7:00 到 10:00（不含 10 点），可以跨午夜（"22-7"）。`user`：`active` 是一分钟内动过键盘鼠标，`idle` 是五分钟以上没动。
- 选场景：条件全满足的场景里，条件越多越优先（"你在不在"算 2 分，时间段算 1 分），一样多选前面的；都不满足用 `default`。
- 用户的选择（当前场景、自动换开关、锁定、关掉的场景）存在身体的 `body-settings.json` 里，不改 look.json。
- 在大脑那边，形象在外形列表里叫 `look:<id>`，它的动作 = 当前场景包的动作 + `scene_<场景>`（去那里）、`scene_stay`（锁定）、`scene_auto`（恢复自动）。换场景算"较长的表演"，她用 play_action 工具做。
- `scene.json` 可以带 `plates`：同一场景其他比例的照片（文件名 `plate_*.png`），各自写尺寸和人物区；身体选和屏幕比例最接近的一张。
- 单独一个包（比如卧室、黑裙）照样能用，就是没有场景切换的外形。

**形象工坊的项目**：`~/Documents/dsh-her 素材/<名字>/`

```
形象.json              项目：角色卡、桌宠和场景、每段片段的动作
参考图提示词.txt        + 参考图.png（用户生成的，也是桌宠的锚点图）
生成清单.md            所有片段：首帧、文件名、提示词（任何工具都能照着做）
MiniMax生成任务.md      同样的清单写成给 MiniMax Code 的任务（选了 MiniMax Code 时）
ComfyUI生成清单.json    同样的清单给脚本用（选了 ComfyUI 时）
桌宠/提示词.txt         + stand_*.mp4
场景-卧室/照片提示词.txt + 提示词.txt + plate.png、scene.json、crop.png（框人物区写的）、片段
```

生成工具可选：MiniMax Code、ComfyUI、即梦、可灵、海螺 AI、通义万相、Vidu，或者手工填写（工具名字、统一设置、每段提示词前面加的词，比如 LoRA 触发词）。选了哪个，每个「提示词.txt」开头就写哪个工具的统一设置。

导入后每部分变成包 `<项目 id>-desk`、`<项目 id>-<场景 id>`（在外形列表里只显示形象本身），再写 look.json。

## 8. 红线

- 角色卡年龄**只能选成年**；任何类型（包括"学妹"这类说法）设定都是成年人。
- 服装和动作不露骨。
- 用真人的脸要本人同意；工坊里上传照片时要确认一次。
- 第三方素材（比如开发期用的同类项目素材）只放本机，不进仓库、不进发布包。
- 样板间里的人物必须是虚构的，生成工具要允许商用。

## 9. 分几步做

| 步 | 内容 | 为什么这个顺序 |
|---|---|---|
| 1 | 屏幕适配：身体报告屏幕信息；铺满时以人物区为准；做场景时画安全区；导入时按屏幕检查分辨率 | 现在的卧室在 16:9 屏上就会切到人，最先修 |
| 2 | 导入增强：自动处理成循环、替换同一个形象并留旧版本、"只重做这几段"的任务文件、报告说原因和办法 | 用户自己做素材马上就用得到 |

## 9.5 分享和广场（2026-10-30 讨论，决定以后再做）

想法：用户觉得自己的形象（或整套设置）做得好，可以分享给所有人；有分类和排行榜。

**判断：方向对，现在不做。**
- 对：形象是这个产品最贵的东西，大多数人不会自己做；同类产品（Wallpaper Engine 创意工坊、Live2D/角色卡社区）都靠用户内容活下来。
- 现在不做：还没有用户（M6 没做、样板间没做），空的排行榜反而显得冷清；公开的用户上传有审核和法律责任（露骨内容、真人的脸、像未成年的角色、盗用素材），国内平台还有审核义务；整套形象几十到上百 MB，存储流量和审核都是持续成本。

**现在**：用已有的"导出到文件夹 / 导入已有项目"。用户自己压缩发到群里、网盘，对方导入。

**以后，按顺序**
1. 官方画廊：只放我们自己做的、审过的形象（就是 §9 的"画廊下载"），没有用户上传，没有审核风险。
2. 看到用户真的在群里互相传形象文件（需求被证明）之后，再做：
   - 分享包：一个 `.herpack` 文件 = 导出的项目 + `share.json`（标题、作者、分类、标签、版本、许可、内容声明）+ 预览图和 10 秒视频。两种粒度："配方"（只有设置，几 KB，拿到后自己生成）和"整套"（带图片和视频，拿到就能用）。永远不含记忆、对你的称呼、key、模型账号、本机路径。
   - 投稿和浏览：先用 GitHub 广场仓库（目录 `index.json`，包放 Releases，国内走 jsDelivr，下载数拿来排行，投稿先审后上架）；量大了再自建服务（账号、点赞、评论、举报）。
   - 分类：类型（配方、整套、桌宠、场景、性格）、画风、主题、性别。排行：近 7 天热门、总下载、最多喜欢、最新、编辑精选。下载按匿名安装 id 去重，"喜欢"要有账号。
   - 工坊加第 6 张卡片"分享这个形象"（发布前自检：成年、没有真人的脸和声音、没有第三方素材、全年龄、选许可，默认"可以用、可以改，不能商用"）；「她」页面加"形象广场"（预览视频，用她的声音试听一句人设，一键用这个，有新版本提示）。

## 12. 工坊怎么把素材变成她（2026-11-01，用户第一次自己做形象时发现）

用户做好图片和视频，上传、保存后在设置里看不到。原因有四个，都是产品的问题：

| 问题 | 现在 |
|---|---|
| 片段要按清单改文件名，否则不算数，也没有提示 | 每一段旁边能单独上传（自动用对的名字）；名字对不上的视频列出来，选"就是这一段"，或者"不用了" |
| 每部分最少 3 段（待机、说话 ×2），比导入程序本身严 | 最少一段待机就能导入；页面说清楚没有说话片段时嘴不会动 |
| "保存"只存设置，导入按钮是灰的，也不说缺什么 | 保存时提醒还要导入；第 5 步逐部分列出这次会不会导入、还差什么 |
| 第 5 步主按钮是"保存"，点了没反应，真正的"导入"不显眼 | 第 5 步去掉"保存"，"导入这个形象"是主按钮；折叠时也显示"还没导入"或"✓ 已导入，她正在用" |
| 场景只能框一块区域，但用户自然会做整张画面都动的视频 | "用整张画面"：不用框，视频盖满照片 |

实测（her-dev，连着桌面身体，用这些素材的副本）：一段绿幕待机和一段 3024×1964 的全屏视频都导入成功，她换上并在壁纸层播放。

**ffmpeg 找不到（2026-11-01）**：从 Dock 打开的 DSH 桌面版，PATH 只有系统目录（`/usr/bin:/bin:/usr/sbin:/sbin`），用户放在 `~/bin` 的 ffmpeg 它看不到；从终端启动的测试环境有完整 PATH，所以之前没测出来。现在大脑会找常见位置、已装好的身体自带的那份，并问一次登录 shell；找到后告诉身体。**以后测试要用干净的 PATH**（`env -i`）启动，才和用户的环境一样。
