# 开发

设计和计划都在这个 `docs/` 文件夹里，从 [P1开发计划.md](P1开发计划.md) 看起；每个阶段的记录是 `M0验证记录.md` 到 `M6记录.md`。

## 组成

- **大脑**（仓库根目录，dsh 插件）：她在 dsh 里的专属会话"她 · 名字"、语音（本地识别 + 云端合成）、身体协议服务（`ws://127.0.0.1:38100` 起）。
- **身体**（`body/`，Electron 桌面程序）：她的形象、字幕气泡、对话小条、三种窗口模式。

两者之间的协议见 [身体协议.md](身体协议.md)。

## 构建和测试

```bash
npm install
npm test
npm run build
```

身体：

```bash
cd body
npm install
npm run build
```

打成一个可以分发的身体程序（mac；输出到 `release/`：zip 和 `body-latest.json`，传到 GitHub Release 后，插件会从 `body.releases` 下载安装、自动更新）：

```bash
cd body
npm run package
```

## 真人桌宠（独立模式）

身体程序加 `--standalone` 就是"真人桌宠"：不连 dsh，小大脑（`src/standalone/pet-brain.ts`）在身体的主进程里跑，数据在系统给应用的文件夹里（`~/Library/Application Support/真人桌宠`、`%APPDATA%\真人桌宠`），不碰 `~/.dsh-her`。设计见 [独立安装包设计](独立安装包设计.md)，进度见 [实施计划](实施计划.md)。

```bash
cd body
npm run build
npx electron . --standalone --home /tmp/zhenren-dev            # 空的：出"把她的设计包拖进来"的窗口
npx electron . --standalone --home /tmp/zhenren-dev 小禾.her    # 像双击设计包一样打开：先预览，点"装进来"
```

- `--home` 只在开发时用，免得动到真的数据文件夹。
- 只要小大脑、不要窗口：`node src/standalone/main.ts --home <文件夹> [--install 设计包.zip]`（在仓库根目录）。
- 设置窗口是 `body/renderer/settings-page.ts`，它能问主进程的事都在 `body/main/standalone.ts` 里（`pet:*`）。
- 打成包以后靠 `resources/app/package.json` 里的 `"standalone": true` 认出自己。
- 聊天（第 11 步）：`src/standalone/pet-chat.ts` 把前台大脑（`src/engine/brains/`）和对话流程（`src/engine/conversation.ts`）接到真人桌宠上。开发时试：设置窗口 → 和她聊天 → 选 Claude Code（要本机 `claude` 已登录），再按 ⌃⌥↩ 打字。加 `--her-mute` 让声音静音播放。
- 打包：`cd body && node scripts/package.mjs --player [--out 文件夹]`，得到 `dsh-her-player-<版本>-<系统>-<芯片>.zip` 和 `player-latest.json`，不碰身体的那两个文件。Mac 上在本机打，Windows 的在 CI 的 `body-windows` 里打（打完启动一次）。
- 试双击 `.her`：把 app 放到普通文件夹里（比如仓库里不进 git 的 `release/`）。放在 `/tmp` 这类临时目录里时，系统不会让它打开任何文件，双击 `.her` 会被"归档实用工具"当成 zip 解开。
- 打好的包默认用真的数据文件夹；试的时候加 `--home <临时文件夹>`。
- "生成安装包"（第 7 步）在 dsh-her 插件里：`src/engine/installer.ts` 从 Release 下载真人桌宠（核对后存在 `~/.dsh-her/player/`），用 `src/core/zip-append.ts` 把 `.her` 和说明.txt 加进它的 zip（原有条目一个字节都不动，符号链接和签名才保得住），存到"下载"。Release 里没有 `player-latest.json` 时会说"还没发布过"。
- 收到安装包的人要用系统自带的解压（双击）。命令行的 `unzip` 解开 Mac 的 app 会坏掉签名，原包也一样，不是追加造成的。
- 试更新（第 6 步）：打两个版本号不同的包，在本机用一个小服务把新的那个包和它的 `player-latest.json` 放出来，用旧的那个包打开，并让它去本机看：`open -n -a 真人桌宠.app --env ZHENREN_UPDATE_BASE=http://127.0.0.1:<端口>/ --args --home <临时文件夹>`。`ZHENREN_UPDATE_BASE` 只认 `http://127.0.0.1:<端口>/`，别的地址一律当没写。开发版（`electron . --standalone`）不会更新自己。

## 测试用的 profile

在一个单独的测试 profile 里运行（数据放在 `~/.dsh-her-dev`，不碰正式的 `~/.dsh-her`）：

```bash
dsh plugin --profile her-dev add link:/path/to/dsh-her
```

profile 的 `cordis.patch.yml`：

```yaml
- id: dsh-her
  name: dsh-her
  config:
    home: ~/.dsh-her-dev
    body:
      launch: auto          # dsh 启动 3 秒后若没有身体连上，就拉起 body/
      pack: ''              # 外形包目录；空 = 身体默认（~/dsh-her-dev-assets/bg2-stacked）
```

```bash
dsh --profile her-dev --no-open --port 3191
```

## 声音

默认用微软 Edge 的声音（通过开源工具 edge-tts，免费，要联网）；找不到已装好的 edge-tts 时会自动装进 `$DSH_HER_HOME/edge-tts`。阿里云百炼 CosyVoice 的 key 放进 mac 钥匙串（或环境变量 `DASHSCOPE_API_KEY`）：

```bash
security add-generic-password -a dsh-her -s dsh-her-dashscope -w
```

本地语音识别模型（约 170 MB，下载到 `$DSH_HER_HOME/models`），以及测速和各音色试听样本：

```bash
DSH_HER_HOME=~/.dsh-her-dev npm run voice:models
DSH_HER_HOME=~/.dsh-her-dev npm run voice:bench
```

## 素材

导入外形包（按 [素材生成提示词.md](素材生成提示词.md) 命名的一个文件夹）：

```bash
node body/scripts/import-pack.ts ~/我的角色 --packs ~/.dsh-her/packs --name 名字
```

合成测试包（色块小人，绿幕；加 `--scene` 是带空场景图的房间）：

```bash
node body/scripts/make-test-pack.mjs ~/dsh-her-dev-assets/test-doll-src
```

开发用素材都放在 `~/dsh-her-dev-assets/`，**不进仓库**。第三方演示素材由 `body/scripts/make-dev-pack.mjs` 转换。

## 发布

1. 根目录和 `body/` 都升版本号：`npm version X --no-git-tag-version`。
2. `cd body && npm run package`，解开 zip 跑 `Contents/MacOS/Electron --smoke`。
3. 提交、推送，等 CI 全过；打标签 `vX` 并推送。
4. `gh release create vX --draft`，带上 mac 的 zip 和 `body-latest.json`；`gh workflow run release-windows.yml -f tag=vX` 打 Windows 身体。
5. 下载 Release 核对 `body-latest.json` 里的大小和校验值，再 `gh release edit vX --draft=false --latest`。
6. `npm publish --access public --otp=<验证码>`。
7. 真人桌宠（等用户说开始发以后）：Mac 上 `cd body && node scripts/package.mjs --player`，Windows 的从 CI 的 `body-windows` 产物里拿；把两个 zip 和合并后的 `player-latest.json` 一起传到同一个 Release。**一旦发过一次，以后每个 Release 都要带上 `player-latest.json`**：真人桌宠每天看的是"最新的 Release"里的这个文件，没有它就显示"没看成"。
