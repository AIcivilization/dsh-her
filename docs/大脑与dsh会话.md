# dsh-her 大脑与 dsh 会话（方案 a 落地设计，草案）

> 已定：每个角色在 dsh 里有一个专属的长期会话。本文说明怎么用 dsh 0.2 的接口实现它。
> 接口依据：dsh `0.2.0-rc.2` 的类型定义，以及 dsh-vael（灵魂引擎）里已经跑通的 `SelfSession` 做法。

---

## 1. 结论：dsh 0.2 需要的接口都有

| 需要 | dsh 0.2 提供的接口 | 参考 |
|---|---|---|
| 创建或恢复她的专属会话 | `agents.create({ sessionId, setup })` / `agents.resume({ resumeSessionId, setup })` | dsh-vael 已跑通 |
| 只在她的会话里替换系统提示词 | `setup` 里调用 `agentCtx.systemPrompt.section({ complete: true })` + `suppressRuntimeContext()` | dsh-vael |
| 只给她的会话注册工具 | `agentCtx.tools.register(...)` | dsh-vael |
| 把你说的话送进去 | `agent.followup(UserMessage)`（新的一轮）/ `agent.steer`（插话）/ `agent.inject`（只补充背景，不触发回复） | |
| 实时拿到她正在生成的字 | 只针对她这个会话的 `agent/assistant-stream` 事件，帧类型有 `start` / `chunk` / `end` | |
| 打断 | `agent.cancel()`。被打断的回复会落成一条带 `interrupted: true` 的 `assistant/message` | |
| 一轮结束 | `turn/end`（带结束原因）、`agent.whenIdle()` | |
| 工具审批改成语音问你 | 只针对她这个会话的 `approval/request` 中间件，返回 `allowed-once` / `rejected` 等 | dsh-watch 监听过这个事件 |
| 她向你提问 | `user-questions/request` | dsh-watch |
| 上下文太长 | dsh 自带自动压缩（`dsh-compaction-basic`） | |
| 会话标题、工作目录 | `sessionTitle.rename`、`workspaceRegistry.create` | dsh-vael |

---

## 2. 会话的生命周期

- **一个角色对应一个会话**。会话 id 记在 dsh-her 自己的数据目录里（不依赖 dsh 去记），重启后恢复同一个会话。
- **标题**：`她 · 苏`，在 dsh 侧栏里能看到，也能直接打字和她聊。
- **工作目录**：`~/.dsh-her/characters/<cid>/room/`，是她自己的小房间，可以放她的日记、照片。
- **恢复失败就新建一个会话**，并把这件事如实记下来（和 dsh-vael 的做法一样），不假装还是原来那个会话。
- **在 dsh 网页里打字也能触发她出声**：她的语音输出挂在"这个会话的生成流"上，不管你是从身体说话、在身体里打字，还是在 dsh 网页里打字，只要有身体连着，她都会开口。

---

## 3. 一轮对话的数据流

```
身体 user.utterance ─► 识别成文字
   ─► agent.inject(现场信息：时间、你在不在、她现在在干什么，很短)
   ─► agent.followup({ text, source: { kind: 'dsh-her', via: 'voice' } })
agent/assistant-stream:
   start ─► speak.begin
   chunk(text) ─► 累积 ─► 解析行内标记 ─► 切句 ─► 合成 ─► speak.seg
   chunk(reasoning / tool-call) ─► 不念
   end ─► 把剩余的半句念完 ─► speak.end
turn/end ─► 状态回到待机
```

**哪些内容会被念出来**：只念正文。
- 思考过程、工具调用不念。
- 代码块不念，改说"代码我放在 dsh 里了"。
- 链接、Markdown 符号在合成之前清理掉（借鉴同类项目的 `clean.ts`）。

---

## 4. 打断

1. 身体在本地立刻停止播放，然后发 `interrupt{uid, seq, playedMs}`。
2. 大脑调用 `agent.cancel()`。dsh 会把**已经生成**的前半段落成 `interrupted: true` 的消息。
3. 但"已生成"不等于"你已听到"。所以下一轮 followup 时，在你这句话前面附一行说明：`（她刚说到"……"就被打断了）`。用 `playedMs` 和每个字的时间点，算出你实际听到的位置。
4. 这样她不会以为你听完了整段话，记忆里也是如实的。

---

## 5. 她的系统提示词（整段替换 dsh 默认的提示词）

dsh 默认是"你是一个编程 agent……"，不适合她。参照 dsh-vael，用 `complete: true` **只在她的会话里**整段替换。内容由几段拼成：

| 段 | 内容 | 来源 |
|---|---|---|
| 人格 | 她是谁、说话方式、和你的关系 | 角色设置（向导生成，可以编辑） |
| 口语规则 | 短句；一次回复一般 1–3 句；不用列表、标题和代码；数字和单位写成口语 | 固定 |
| 表演标记 | 怎么用 `〔开心〕`、`〔动作:wave〕` 这类标记（见第 6 节），只能用现有外形包里有的 | 根据身体连接时报告的能力**自动生成** |
| 能力边界 | 前期：她只陪你聊天，不能操作电脑。被要求干活时要坦白说"这个我现在还做不了"，不要假装做了 | 固定 |
| 关于你 | 你的称呼、偏好（来自记忆接口，很短） | 记忆接口 |

注意：表演标记那段**随外形包变化**。换了外形包，下一轮的系统提示词就跟着更新，所以她只会用这个外形包里真实存在的动作。

## 6. 情绪和动作怎么从模型传到身体

两种方式，按动作的轻重选：

| 方式 | 例子 | 延迟 | 适合 |
|---|---|---|---|
| **行内标记**（推荐默认） | `〔开心〕今天天气真好呀〔动作:wave〕` | **零额外延迟**：从生成流里直接解析，标记本身不念出来 | 情绪、挥手、点头这类轻动作 |
| **工具调用** `play_action` | 换装展示、出门再回来 | 多一次模型调用（要等动作结果再接着说） | 重动作、需要知道动作播完的情况 |

用户看到的文字里不出现标记：dsh 网页显示的是原文，可以注册一个显示过滤把标记去掉。这一点还要验证 dsh 0.2 有没有对应接口。

---

## 7. 她能用哪些工具

**已定（2026-10-28）：前期她不干活。** 她的会话只用于陪伴聊天，不注册任何操作电脑的工具。

### 前期（P1）

| 工具 | 作用 |
|---|---|
| `play_action` | 播放重动作（第 6 节） |
| `remember` / `recall` | 记忆接口，**只用 dsh-her 内置的简单实现** |

这样做的好处：
- 她的会话里不会出现工具输出，上下文干净，开口快，人格稳定。
- 不需要审批，也就不会出现"她突然问你要不要删文件"的情况。

### 以后（干活阶段，现在不做，只保留设计）

- 加 `delegate_task`：把真正的活交给一个新开的 dsh 工作会话，干完把结果摘要告诉她，由她转述给你。她自己的会话依然不直接用 bash、读写文件，理由同上。
- 审批：工作会话需要审批时，由 dsh-her 接住，变成她用语音问你；dsh 网页里的审批卡片同时保留，哪边先回答算哪边。

---

## 8. 模型和速度

- 她的会话默认使用 dsh 当前选中的模型，也可以给每个角色单独指定。**语音场景建议用不带思考过程的快速模型**，思考模型会明显增加开口前的等待。
- 每轮注入的"现场信息"要短，控制在 100 字以内。
- 长期会话靠 dsh 自动压缩。人格在系统提示词里，压缩不会冲淡它。以后可以考虑"每天换一个新会话，并带上前一天的摘要"，先不做。

---

## 9. 多角色

- 每个角色一个独立会话。
- 导演决定你这句话交给谁（你叫了谁的名字；没叫名字就交给最近说话的那个）。
- 其他角色通过 `agent.inject` 知道"苏刚才说了什么"，但**不触发回复**，只更新背景。要让两个角色互相聊天，需要手动开启（耗 token）。

## 10. 决定记录

| 问题 | 结论 |
|---|---|
| 她的工具 | **前期不干活**：只有 `play_action` 和 `remember` / `recall`（2026-10-28） |
| 灵魂引擎（dsh-vael） | **先不接**。记忆只用 dsh-her 内置的简单实现，但记忆接口按"以后可替换"来设计（2026-10-28）。dsh-vael 只作为"怎么建专属会话"的代码参考，不产生依赖 |
| 表演方式 | 按推荐：行内标记为主，重动作用工具调用（未提出异议） |
| 标记在 dsh 网页里的显示 | 先查 dsh 有没有显示过滤的接口；没有就先接受网页里能看到 `〔开心〕` |
| 数据目录 | 按推荐：`~/.dsh-her/` |
