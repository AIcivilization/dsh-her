# 设计：生成独立安装包（讨论中，2026-11-14，还没写代码）

> 用户的想法：在总览里加一个选项，把调好的她一键打包成安装包。拿到安装包的人**不用装 dsh**，像普通应用一样装上，她就住在桌面背景里、活在桌面上。这一份是思考和方案，等用户拍板再做。

## 已经定了的

逐条记在这里，每条写决定和理由。

1. **第一版只做桌宠版**（2026-11-14）。不聊天、不联网、不要 key：住在壁纸里、浮在桌面上、按编排换场景、碰她有反应、说设计包里写好的台词、开机动画。聊天版作为第二步紧接着做。
   理由：快、稳；不涉及 API key、账号和隐私，拿到安装包的人打开就能玩；聊天要先把对话逻辑从 `src/dsh/plugin.ts` 抽出来，工作量大，不该卡住第一版。
2. **设计包不塞进 app。Mac 上放在 app 旁边，做成能双击打开的文件；Windows 放进文件夹里**（2026-11-14）。
   - Mac：设计包就是设计包格式的 zip，只是扩展名改成能双击的（暂定 `.her`，比如 `小禾.her`；播放器也认 `.zip`）。播放器在 Info.plist 里登记这种文件，双击它就打开播放器并装进去。播放器第一次打开时如果还没有设计包，就出一个小窗："把她的设计包拖进来"（或点一下选文件）。
   - Windows：`design.zip` 直接放进播放器的文件夹里，打开就有；以后也能双击 `.her` 换一个她。
   理由：
   - Mac 上从网上下载、没正式签名的 app，第一次在解压的地方打开时，系统会把它挪到一个随机的临时位置运行（Gatekeeper 的 App Translocation），看不到旁边的文件；用户把 app 拖进"应用程序"后，旁边的文件也留在原地了。所以不能靠"在旁边找"，要靠双击和拖进来。
   - 塞进 app 里要重新签名：只有在 Mac 上生成时能用系统自带的 codesign 临时重签，在 Windows 上生成 Mac 包做不到；以后有了正式签名，在用户电脑上塞进去会把签名弄坏，没法再签。
   - Windows 的程序是一个文件夹，签名只管 exe 本身，旁边多一个文件不影响。
   - 好处不变：同一个播放器能放任何设计包。
3. **播放器叫"真人桌宠"，文件名一律是"真人桌宠"**（2026-11-14）。`真人桌宠.app`、`真人桌宠.exe`，不跟着设计包改名；托盘和窗口里显示她的名字（从设计包读）。
   理由：
   - 给不懂技术的人一个一看就懂的名字；dsh-her 这个名字留给 dsh 里的插件，插件不改名。
   - 程序是通用的，换一个设计包不用换程序，电脑上只装一个。
   由此带来的做法：
   - "真人桌宠"和 dsh 里的身体是**同一份代码，打两个包**：名字、应用标识（bundle id）、图标说明、数据文件夹各用各的。这样同一台电脑上既装了 dsh-her 又装了真人桌宠也不打架：双击 `.her` 文件一定是真人桌宠打开，两边的人物和素材互不影响。
   - 真人桌宠的数据放在系统给应用的文件夹里（Mac：`~/Library/Application Support/真人桌宠/`，Windows：`%APPDATA%\真人桌宠\`），不碰 `~/.dsh-her`。
   - 名字里有"真人"，所以生成安装包时那句提醒要更显眼：真人的脸和声音要本人同意。
4. **第一版不做正式签名；苹果的以后申请，微软的先不做**（2026-11-14）。
   - 第一版 Mac 包还是临时签名（ad-hoc，和现在的身体一样），带一份说明书发出去试。
   - 打包脚本里留好"签名 + 公证"的位置：等用户本人申请了苹果开发者账号（每年 99 美元，要实名，不能代办），把证书接上就行，不用再改流程。
   - 微软的代码签名证书更贵（一年几百美元）、申请更麻烦，而 Windows 的拦截本来就容易过，先不做。
   理由：先看有没有人用，再花钱；但 Mac 那道坎是实在的，所以不是"不做"，是"以后做"。
   要写进说明书的（讨论稿原来写的"右键 → 打开"已经不对了）：
   - Mac（macOS 15 及以后）：双击会被拦。去"系统设置 → 隐私与安全性"，往下找到"真人桌宠"那一行，点"仍要打开"。只要做一次。
   - Windows：出现"Windows 已保护你的电脑"时，点"更多信息 → 仍要运行"。

## 1. 先说结论

- **能做，而且设计包格式正好是关键**：安装包 = 我们提前做好的"播放器"程序 + 一个设计包。
- **"生成安装包"不需要在用户电脑上编译**：从我们的 GitHub Release 下载对应系统的播放器，旁边放上从现在的她导出的设计包，打成一个 zip。Mac 上也能生成 Windows 的，反过来也行。
- **难点不在打包，在"大脑"**：现在她的对话、记忆用的是 dsh 的模型和会话。没有 dsh，要么她不聊天（只当桌宠），要么让拿到安装包的人填自己的 API key。建议分两步走。

## 2. 现在的东西哪些能直接用

| 部分 | 现在在哪 | 不用 dsh 能不能用 |
|---|---|---|
| 身体（Electron 桌面程序：壁纸里、浮在桌面上、触摸、拖动、大小、开机动画、托盘） | `body/` | **能**：它本来就是独立程序，只通过本机的协议和大脑说话 |
| 协议服务（身体连大脑的那一头） | `src/server/` | **能**：不依赖 dsh |
| 编排、外形包、形象、素材检查 | `src/pack/` | **能** |
| 人设、提示词、声音（Edge、Ming）、记忆、说话断句 | `src/core/`、`src/voice/`、`src/memory/` | **能**：当初就规定这些不依赖 dsh |
| 她的会话（模型、工具、对话记录） | `src/dsh/her-session.ts` | **不能**：用的是 dsh 的 agents 服务 |
| 设置页 | `src/client/`（React 网页） | 网页本身能用，但现在挂在 dsh 的页面里 |
| 皮肤 | 换的是 dsh 的界面 | 没有 dsh 就没有意义，安装包里不带 |

另外，`src/dsh/` 里很多文件其实也不依赖 dsh，只是放在那个文件夹里：按编排换场景（`stage-play.ts`）、先开口（`initiative.ts`）、素材库（`library.ts`）、人物（`characters.ts`）、设计包装进来和导出（`design-packs.ts`）等。真正离不开 dsh 的只有 `her-session.ts`、`plugin.ts`、`design-session.ts`、`api.ts`、`config.ts`。

**播放器不用另写一个程序，就是现在的身体 app 换个名字再打一个包（叫"真人桌宠"）。** 身体本来就打包好发在 Release 上（`dsh-her.app`、`dsh-her` 文件夹里的 `dsh-her.exe`，`body/scripts/package.mjs` 做的），而且它是 Electron，自带 Node，所以小大脑可以直接放进身体 app 里，在 Electron 的后台进程里跑。身体启动时如果有 dsh 来连（`DSH_HER_URL`，或者 `brain.json`），就照旧连 dsh；如果是独立安装包启动的，就自己起这个小大脑，再用同一套协议连上它。Windows 的身体里已经带了 ffmpeg，图片转视频也够用（Mac 版要确认带不带）。

所以要新写的是一个**独立的小大脑**（`src/standalone/`）：用上面那些能用的部分，桌宠版只要编排、触摸、台词；第二步再加一个不依赖 dsh 的对话模块，和一个自己的小设置窗口。身体只改启动时"连谁"这一处。

## 3. 安装包里是什么

```
她-小禾-mac.zip
├── 真人桌宠.app        身体 + 独立小大脑，和我们 Release 上的一模一样
├── 小禾.her            设计包（就是设计包格式的 zip）：从现在的她导出的
└── 说明.txt            先把 app 拖进"应用程序"，打开一次，再双击 小禾.her

她-小禾-windows.zip
└── 真人桌宠/
    ├── 真人桌宠.exe 和它的文件
    ├── design.zip      设计包，打开就有
    └── 说明.txt
```

- **设计包不塞进 app**，见上面"已经定了的" 2。
- **Windows** 先用 zip（安装程序的事见第 6 节）。
- **大小**：Mac 约 150 MB，Windows 约 210 MB，加上设计包（看素材多少，一般几 MB 到几十 MB）。
- **不会带的**：记忆、对话、模型设置、API key、皮肤。

## 4. 拿到安装包的人能玩到什么（分两步）

**第一步：桌宠版（不聊天，不联网，不要 key）**

- 住在壁纸里、浮在桌面上（四个开关里的两个）、大小、托盘图标；
- 按编排换场景：时间段、你在不在、隔一会儿随机；
- 碰她有反应，说几句设计包里写好的话（设计包里加一个可选的 `lines`：被摸头、打招呼、晚安……，见下文）；
- 开机动画；
- 一个很小的设置窗口：开关、大小、换一个设计包、退出。

这一步大脑很小，主要是把编排变成"现在显示什么"（这段代码已经有），基本不会出错，也不涉及任何账号和隐私。

**第二步：能聊天（拿到的人填自己的 key）**

- 第一次打开问"要不要和她聊天"：填一个 DeepSeek（或 OpenAI 兼容）的 API key，存进系统钥匙串（Mac）或权限 600 的文件（Windows），绝不进安装包；
- 对话小条、头顶气泡、纯聊模式、Edge 的声音（免费，要联网）、记忆、先开口；
- 听你说话（本机识别模型，第一次用时下载）；本机 Ming 声音（Mac）。

第二步的工作量主要在"不依赖 dsh 的对话模块"：发请求、流式拿回答、断句给声音、保存对话、把记忆和人设放进提示词。这些逻辑现在散在 `src/dsh/plugin.ts` 里，要先抽出来，dsh 版和独立版共用。

## 5. "生成安装包"怎么用

在总览（或「设计包」页）加一个"生成安装包"：

1. 选给谁用：Mac（Apple 芯片）、Windows，或两个都要；
2. 选带哪几部分（和"导出设计包"一样：人设、编排和素材、三视图、开机动画），填作者和许可；
3. 程序去我们的 Release 下载对应的播放器（第一次要下载，约 150–210 MB，**下载前先问**），和设计包一起打成 zip，存到"下载"文件夹；
4. 提示：
   - 素材里有别人的图、视频、字体时，要有对方的许可才能发出去；许可写"仅个人使用"的设计包不能生成给别人。
   - 我们没有苹果和微软的签名证书，对方第一次打开会被系统拦：Mac 要去"系统设置 → 隐私与安全性"点"仍要打开"，Windows 要点"更多信息 → 仍要运行"。安装包里的说明.txt 会写清楚。
