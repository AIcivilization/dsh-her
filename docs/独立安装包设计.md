# 设计：生成独立安装包（2026-11-14 讨论完；实施见 [实施计划](实施计划.md)）

> 用户的想法：在总览里加一个选项，把调好的她一键打包成安装包。拿到安装包的人**不用装 dsh**，像普通应用一样装上，她就住在桌面背景里、活在桌面上。下面八件事已经和用户一条一条定了；第 7 节是按顺序的实施计划。

## 已经定了的

逐条记在这里，每条写决定和理由。

1. **第一版只做桌宠版**（2026-11-14）。不聊天、不要 key，除了检查更新（见 6）不联网：住在壁纸里、浮在桌面上、按编排换场景、碰她有反应、说设计包里写好的台词、开机动画。聊天版作为第二步紧接着做。
   理由：快、稳；不涉及 API key、账号和隐私，拿到安装包的人打开就能玩；聊天要先把对话逻辑从 `src/dsh/plugin.ts` 抽出来，工作量大，不该卡住第一版。
2. **设计包不塞进 app。Mac 上放在 app 旁边，做成能双击打开的文件；Windows 放进文件夹里**（2026-11-14）。
   - Mac：设计包就是设计包格式的 zip，只是扩展名改成能双击的（暂定 `.her`，比如 `小禾.her`；播放器也认 `.zip`）。播放器在 Info.plist 里登记这种文件，双击它就打开播放器并装进去。播放器第一次打开时如果还没有设计包，就出一个小窗："把她的设计包拖进来"（或点一下选文件）。
   - Windows：`design.zip` 直接放进播放器的文件夹里，打开就有；以后也能双击 `.her` 换一个她。
   理由：
   - Mac 上从网上下载、没正式签名的 app，第一次在解压的地方打开时，系统会把它挪到一个随机的临时位置运行（Gatekeeper 的 App Translocation），看不到旁边的文件；用户把 app 拖进"应用程序"后，旁边的文件也留在原地了。所以不能靠"在旁边找"，要靠双击和拖进来。
   - 塞进 app 里要重新签名：只有在 Mac 上生成时能用系统自带的 codesign 临时重签，在 Windows 上生成 Mac 包做不到；以后有了正式签名，在用户电脑上塞进去会把签名弄坏，没法再签。
   - Windows 的程序是一个文件夹，签名只管 exe 本身，旁边多一个文件不影响。
   - 好处不变：同一个播放器能放任何设计包。
3. **播放器叫"真人桌宠"，文件名一律是"真人桌宠"**（2026-11-14）。`真人桌宠.app`、`真人桌宠.exe`，不跟着设计包改名；托盘和窗口里显示她的名字（从设计包读）。
   理由：
   - 给不懂技术的人一个一看就懂的名字；dsh-her 这个名字留给 dsh 里的插件，插件不改名。
   - 程序是通用的，换一个设计包不用换程序，电脑上只装一个。
   由此带来的做法：
   - "真人桌宠"和 dsh 里的身体是**同一份代码，打两个包**：名字、应用标识（bundle id）、图标说明、数据文件夹各用各的。这样同一台电脑上既装了 dsh-her 又装了真人桌宠也不打架：双击 `.her` 文件一定是真人桌宠打开，两边的人物和素材互不影响。
   - 真人桌宠的数据放在系统给应用的文件夹里（Mac：`~/Library/Application Support/真人桌宠/`，Windows：`%APPDATA%\真人桌宠\`），不碰 `~/.dsh-her`。
   - 名字里有"真人"，所以生成安装包时那句提醒要更显眼：真人的脸和声音要本人同意。
4. **第一版不做正式签名；苹果的以后申请，微软的先不做**（2026-11-14）。
   - 第一版 Mac 包还是临时签名（ad-hoc，和现在的身体一样），带一份说明书发出去试。
   - 打包脚本里留好"签名 + 公证"的位置：等用户本人申请了苹果开发者账号（每年 99 美元，要实名，不能代办），把证书接上就行，不用再改流程。
   - 微软的代码签名证书更贵（一年几百美元）、申请更麻烦，而 Windows 的拦截本来就容易过，先不做。
   理由：先看有没有人用，再花钱；但 Mac 那道坎是实在的，所以不是"不做"，是"以后做"。
   要写进说明书的（讨论稿原来写的"右键 → 打开"已经不对了）：
   - Mac（macOS 15 及以后）：双击会被拦。去"系统设置 → 隐私与安全性"，往下找到"真人桌宠"那一行，点"仍要打开"。只要做一次。
   - Windows：出现"Windows 已保护你的电脑"时，点"更多信息 → 仍要运行"。
5. **桌宠版的台词只出气泡文字，没有声音**（2026-11-14）。声音留到聊天版一起做。
   理由：桌宠版说好了完全不联网；免费的 Edge 声音要联网；设计包格式现在不收声音文件，为第一版去扩格式不值得。
   台词从哪来：设计包格式加一个可选的 `lines`（旧引擎不认识会忽略，不用改格式版本）。
   ```json
   "character": {
     "lines": {
       "touch": { "head": ["嗯？"], "body": ["怎么啦？"], "long": ["嗯……"], "many": ["好啦好啦。"] },
       "hello": ["我来啦。"],
       "night": ["不早了，去睡吧。"]
     }
   }
   ```
   - `touch` 的四种（摸头、摸身体、长按、连着摸）就是现在 `src/core/touch.ts` 里那四种。dsh-her 里每个人物已经有一套（她的模型按人设写好存着的），导出设计包时直接带上；没有时用引擎自带的那几句中性的。
   - `hello`（出场时）、`night`（安静时段开始时）是可选的，没有就不说。以后要加别的时机再加名字。
   - 每句 40 个字以内，每种最多 20 句。
6. **自动检查更新，有新版在托盘提醒，点了才下载**（2026-11-14）。
   - 每天联网看一次我们 Release 上的版本清单（只取一个很小的文件，不发送任何关于用户的东西）；有新版时托盘图标上出一个提醒，菜单里多一项"更新到 x.y.z"。
   - 点了才下载；下载完核对 SHA-256，对了才换上，旧版留一份可以退回（和 dsh-her 现在更新身体的做法一样，用 `src/engine/body-install.ts` 那套，下载线路也一样）。
   - 设置窗口里有开关"自动检查更新"，默认开；关了就完全不联网，另有一个"现在检查"按钮。
   - 所以桌宠版对外的说法要改成：**不要账号、不要 key，除了每天看一次有没有新版以外不联网**（说明书和设置窗口里都照实写）。
   理由：旧版的问题不该一直留在别人电脑上；以后出聊天版时，已经装了桌宠版的人能直接升上去。
   要注意的：Mac 上如果程序还在被系统挪到临时位置运行（没拖进"应用程序"），没法换掉自己，这时提醒改成"先把真人桌宠拖进应用程序"。
7. **Windows 第一版用 zip，不做安装程序**（2026-11-14）。解压出"真人桌宠"文件夹，双击 `真人桌宠.exe` 就有她（设计包已经在文件夹里）。
   - 程序发现自己是在压缩包里直接被双击的（在系统的临时文件夹里运行）时，出一句提示："请先把压缩包解压出来，再打开"，然后退出。
   - 没有开始菜单和卸载项：设置窗口里有"开机自动启动"开关；卸载就是退出后删掉文件夹（说明书里写，并写清数据在 `%APPDATA%\真人桌宠\`）。
   - 第一次运行时在当前用户下登记 `.her` 文件（不要管理员权限），以后双击设计包就能换一个她。
   理由：在 Mac 上也能生成 Windows 包，不需要别的工具；解压、双击两步就有她。没签名的安装程序同样会被拦，并不更顺。真正的安装程序（NSIS，在 CI 里做）等有了签名再做。
8. **总览放入口，功能在「设计包」页**（2026-11-14）。总览上有一个显眼的"生成安装包"，点了跳到「外观 → 设计包」页的"生成安装包"那一块。
   理由：生成安装包要填的东西（带哪几部分、作者、版本、许可、说明）和"导出设计包"完全一样，只多了选系统和下载播放器；放在一起共用一套选项，不写两遍。总览上留入口，是因为这是给别人看成果的一步，要让人找得到。

## 1. 先说结论

- **能做，而且设计包格式正好是关键**：安装包 = 我们提前做好的"播放器"程序 + 一个设计包。
- **"生成安装包"不需要在用户电脑上编译**：从我们的 GitHub Release 下载对应系统的播放器（叫"真人桌宠"），加上从现在的她导出的设计包，就是一个 zip。Mac 上也能生成 Windows 的，反过来也行。
- **难点不在打包，在"大脑"**：现在她的对话、记忆用的是 dsh 的模型和会话。没有 dsh，要么她不聊天（只当桌宠），要么让拿到安装包的人填自己的 API key。分两步走：先做桌宠版，再做聊天版。

## 2. 现在的东西哪些能直接用

| 部分 | 现在在哪 | 不用 dsh 能不能用 |
|---|---|---|
| 身体（Electron 桌面程序：壁纸里、浮在桌面上、触摸、拖动、大小、开机动画、托盘） | `body/` | **能**：它本来就是独立程序，只通过本机的协议和大脑说话 |
| 协议服务（身体连大脑的那一头） | `src/server/` | **能**：不依赖 dsh |
| 编排、外形包、形象、素材检查 | `src/pack/` | **能** |
| 人设、提示词、声音（Edge、Ming）、记忆、说话断句 | `src/core/`、`src/voice/`、`src/memory/` | **能**：当初就规定这些不依赖 dsh |
| 她的会话（模型、工具、对话记录） | `src/dsh/her-session.ts` | **不能**：用的是 dsh 的 agents 服务 |
| 设置页 | `src/client/`（React 网页） | 网页本身能用，但现在挂在 dsh 的页面里 |
| 皮肤 | 换的是 dsh 的界面 | 没有 dsh 就没有意义，安装包里不带 |

另外，`src/dsh/` 里很多文件其实也不依赖 dsh，只是放在那个文件夹里（实施第 2 步已经把它们挪到 `src/engine/`）：按编排换场景（`stage-play.ts`）、先开口（`initiative.ts`）、素材库（`library.ts`）、人物（`characters.ts`）、设计包装进来和导出（`design-packs.ts`）等。真正离不开 dsh 的只有 `her-session.ts`、`plugin.ts`、`design-session.ts`、`api.ts`、`config.ts`。

**播放器不用另写一个程序，就是现在的身体 app 换个名字再打一个包（叫"真人桌宠"）。** 身体本来就打包好发在 Release 上（`dsh-her.app`、`dsh-her` 文件夹里的 `dsh-her.exe`，`body/scripts/package.mjs` 做的），而且它是 Electron，自带 Node，所以小大脑可以直接放进身体 app 里，在 Electron 的后台进程里跑。身体启动时如果有 dsh 来连（`DSH_HER_URL`，或者 `brain.json`），就照旧连 dsh；如果是独立安装包启动的，就自己起这个小大脑，再用同一套协议连上它。Mac 和 Windows 的身体里都已经带了 ffmpeg（`package.mjs` 放进去的），编排里的图片转成视频够用。

所以要新写的是一个**独立的小大脑**（`src/standalone/`）：用上面那些能用的部分，桌宠版只要编排、触摸、台词；第二步再加一个不依赖 dsh 的对话模块，和一个自己的小设置窗口。身体只改启动时"连谁"这一处。

## 3. 安装包里是什么

```
真人桌宠-小禾-mac.zip
├── 真人桌宠.app        身体 + 独立小大脑，和我们 Release 上的一模一样
├── 小禾.her            设计包（就是设计包格式的 zip）：从现在的她导出的
└── 说明.txt            先把 app 拖进"应用程序"，打开一次，再双击 小禾.her

真人桌宠-小禾-windows.zip
└── 真人桌宠/
    ├── 真人桌宠.exe 和它的文件
    ├── design.zip      设计包，打开就有
    └── 说明.txt
```

- **设计包不塞进 app**，见上面"已经定了的" 2。
- **Windows** 第一版用 zip，见上面"已经定了的" 7。
- **大小**：Mac 约 150 MB，Windows 约 210 MB，加上设计包（看素材多少，一般几 MB 到几十 MB）。
- **不会带的**：记忆、对话、模型设置、API key、皮肤。

## 4. 拿到安装包的人能玩到什么（分两步）

**第一步：桌宠版（不聊天，不要 key，除了检查更新不联网）**

- 住在壁纸里、浮在桌面上（四个开关里的两个）、大小、托盘图标；
- 按编排换场景：时间段、你在不在、隔一会儿随机；
- 碰她有反应，头顶气泡里出一句设计包里写好的话（只有文字，没有声音；见上面"已经定了的" 5）；
- 开机动画；
- 一个很小的设置窗口（里面有什么见第 6 节）。

这一步大脑很小，主要是把编排变成"现在显示什么"（这段代码已经有），基本不会出错，也不涉及任何账号和隐私。

**第二步：能聊天（拿到的人填自己的 key；不在这一轮）**

- 第一次打开问"要不要和她聊天"：填一个 DeepSeek（或 OpenAI 兼容）的 API key，存进系统钥匙串（Mac）或权限 600 的文件（Windows），绝不进安装包；
- 对话小条、头顶气泡、纯聊模式、Edge 的声音（免费，要联网）、记忆、先开口；
- 听你说话（本机识别模型，第一次用时下载）；本机 Ming 声音（Mac）。

第二步的工作量主要在"不依赖 dsh 的对话模块"：发请求、流式拿回答、断句给声音、保存对话、把记忆和人设放进提示词。这些逻辑现在散在 `src/dsh/plugin.ts` 里，要先抽出来，dsh 版和独立版共用。

## 5. "生成安装包"怎么用

总览上点"生成安装包"，跳到「设计包」页的这一块：

1. 选给谁用：Mac（Apple 芯片）、Windows（64 位），或两个都要。在哪种电脑上都能生成另一种的；在 VPS 的网页里也能生成。
2. 选带哪几部分（和"导出设计包"共用：人设和台词、编排和它用到的素材、三视图、开机动画），填名字、作者、版本、许可、说明。皮肤不带（没有 dsh 就没有意义）。
3. 程序去我们的 Release 下载"真人桌宠"（约 150–210 MB，**下载前先问**；下载过的同一版留在 `<home>/player/` 里，下次不用再下），核对 SHA-256，把设计包和说明书加进去，存到"下载"文件夹：`真人桌宠-小禾-mac.zip`、`真人桌宠-小禾-windows.zip`。
4. 生成前的提醒（要勾"我确认"才能生成）：
   - **真人的脸和声音要本人同意。**
   - 素材里有别人的图、视频、字体时，要有对方的许可才能发出去。
   - 许可写"仅个人使用"之类不许转发的设计包，不能生成给别人。
   - 编排里用了"外形包"的格子不会带上（和导出设计包一样，会列出来）。
5. 生成后告诉用户：对方第一次打开会被系统拦一次，怎么过写在包里的说明.txt 里（见"已经定了的" 4）。

不会带的：记忆、对话、模型设置、API key、皮肤。

## 6. 没有问用户、我先定下的细节（不同意就改）

- **只有 Mac（Apple 芯片）和 Windows（64 位）**：现在身体只打这两种，真人桌宠跟着来。Intel 的 Mac、Linux 先没有。
- **安装包里的真人桌宠是生成那一刻的最新版**；对方装上以后靠自动检查更新跟上。
- **可以装好几个她**：再双击一个 `.her`，多一个人物（不覆盖原来的），在设置窗口里换。用的就是现在"多个人物"那套。
- **没有设计包时不显示任何人**：真人桌宠里不带我们自己的设计，第一次打开没有设计包就出"把她的设计包拖进来"的小窗。
- **小设置窗口里有**：现在是谁（换人物、装一个设计包、移走）、住在哪（壁纸里 / 浮在桌面上两个开关）、大小、安静时段、开机自动启动、自动检查更新、关于（版本；设计包的作者、许可、主页；"身体引擎：dsh-her"）、退出。从托盘图标打开。
- **装设计包时照样先预览**：封面、作者、**许可**、里面有什么，点了"装进来"才装；SVG 里能运行的东西照样去掉。双击来的文件也一样，不会不问就装。
- **我们的 Release 上也单独放真人桌宠**（和安装包里的一模一样）：拿到一个 `.her` 的人可以自己去下载播放器。
- **生成 Mac 包时不重新压缩播放器**：往下载好的播放器 zip 里加文件，原有的条目原样照抄，这样 app 里的可执行权限和符号链接不会丢（在 Windows 上生成 Mac 包也不会坏）。
- **对外发的播放器里的 ffmpeg** 要选定一个构建并带上它的许可说明（`package.mjs` 里早就写了这条，发真人桌宠时必须落实）。

## 7. 实施计划（最初的八步；后来并进了 [实施计划](实施计划.md) 的第 1–8 步，以那一份为准）

每一步做完都能单独验收，前一步不依赖后一步。

**第 1 步：设计包格式加台词（`lines`）**
- `docs/设计包格式.md` 加 `character.lines`（见"已经定了的" 5）；`src/core/design-pack.ts` 读、检查（字数、句数）、写。
- 导出时带上这个人物已有的触摸台词；装进来时存成那个新人物的台词。
- 验收：导出再装回来，台词一句不差；旧设计包（没有 `lines`）照常能装。

**第 2 步：把不依赖 dsh 的东西从 `src/dsh/` 挪出来**
- `stage-play.ts`、`initiative.ts`、`library.ts`、`characters.ts`、`design-packs.ts`、`stage-store.ts`、`body-install.ts` 里通用的下载和校验等，挪到不带 dsh 名字的文件夹（比如 `src/engine/`），`plugin.ts` 改成从新位置引用。只挪位置，不改行为。
- 加一条检查（测试里）：`src/engine/`、`src/core/`、`src/pack/`、`src/server/` 不许引用 `src/dsh/` 和 dsh 的包。
- 验收：现有测试全过；dsh 里的她和原来一样。

**第 3 步：独立小大脑（桌宠版）`src/standalone/`**
- 起协议服务（`src/server/brain-server.ts`），数据文件夹用系统给应用的那个（"已经定了的" 3）。
- 做的事：读现在的人物和编排 → 告诉身体现在显示什么（时间段、在不在、随机）；触摸 → 挑一句台词 → 气泡；`hello`、`night` 台词；开机动画；装设计包（预览 → 装）、换人物、移走。
- 不做的：模型、对话、声音、听、记忆、皮肤。身体发来这些消息时回"这一版没有"。
- 验收：用 `env -i` 的干净环境、不装 dsh，命令行起小大脑 + 开发版身体，装一个设计包，她按编排出现，碰她出台词。

**第 4 步：身体认"独立模式"，加小设置窗口**
- 身体启动时看自己是不是"真人桌宠"这个包：是，就在 Electron 的后台进程里起小大脑并连上它；不是，照旧连 dsh。
- 没有设计包时的"拖进来"小窗；双击 `.her`（Mac 的文件登记，Windows 第一次运行时在当前用户下登记）；托盘菜单和小设置窗口（第 6 节列的那些）。
- Windows：发现自己在压缩包的临时文件夹里运行时提示先解压。Mac：被系统挪到临时位置运行时，提示先拖进"应用程序"。
- 对话小条、麦克风这些聊天用的入口在独立模式下不出现。
- 验收：Mac、Windows 各一台没装 dsh 的电脑（或干净用户），按说明书从零走一遍。

**第 5 步：打"真人桌宠"的包并发到 Release**
- `body/scripts/package.mjs` 加一种打法：名字、应用标识、图标说明、文件登记都是真人桌宠的，里面带小大脑。Mac 还是临时签名，脚本里留好"签名 + 公证"的位置。
- Release 上多两个文件和一个清单：`dsh-her-player-<版本>-darwin-arm64.zip`、`…-win32-x64.zip`（Release 上的文件名用英文，下载地址里不出现中文；解开以后是"真人桌宠"）、`player-latest.json`（版本、大小、SHA-256）。Windows 的在 CI 里打（`release-windows.yml` 加一步），Mac 的和现在的身体一样打。
- ffmpeg 的构建和许可说明定下来，放进包里。
- 验收：从 Release 下载的包，在没装 dsh 的电脑上能打开、能装设计包。

**第 6 步：自动检查更新**
- 每天看一次 `player-latest.json`，托盘提醒，点了才下载，核对后换上，留一份旧版；开关和"现在检查"按钮。
- 验收：装一个旧版，发一个新版，能提醒、能升上去、能退回；关了开关以后抓不到任何联网。

**第 7 步："生成安装包"**
- 大脑这边：下载（先问）、校验、缓存播放器；导出设计包；往播放器 zip 里加设计包和说明.txt（原条目照抄）；存到"下载"文件夹。
- 设置页：「设计包」页的"生成安装包"一块（和导出共用选项、提醒和"我确认"）；总览上的入口。
- 说明.txt 两份（Mac、Windows），写清怎么打开、怎么过系统拦截、怎么卸载、每天会看一次更新。
- 验收：在 Mac 上生成两种包，各在对应的干净电脑上按说明书走通；在 Windows 上生成 Mac 包，Mac 上能打开（权限和符号链接没丢）。

**第 8 步：文档和对外说法**
