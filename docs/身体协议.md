# dsh-her 身体协议与形象接口（草案 v0.2）

> "大脑"指 dsh-her 插件（运行在 dsh 的 node 端）。"身体"指桌面程序（P1 用 **Electron** 做视频版，以后可能有 Unity、手机等其他实现）。

**已定（2026-10-28）：**
- 视频版身体用 Electron。
- 她的对话放在 dsh 里每个角色专属的长期会话中（第 11 节方案 a）。
- 端口由大脑自己管理，被占用就自动换一个可用的，实际端口写进发现文件。
- 默认插话模式，加回声消除；效果不好时自动退回排队模式。
- 片段能不能被中途打断，由外形包里每个片段的 `interruptible` 标记决定。

---

## 0. 原则

1. **大脑厚，身体薄**。能放在大脑的逻辑都放大脑：导演、轮流说话、何时打断、记忆、语音合成和识别。身体只保留**对延迟敏感**的部分：判断你开没开口、播放、点击命中、画面。
2. **大脑只说"要什么"，身体决定"怎么演"**。大脑说"开心地说这句话"；身体自己决定播哪段视频、做哪个 3D 表情。
3. **能力靠声明，做不到就降级**。身体连上来先报告自己会什么，大脑只按这些能力下指令。
4. **灵魂在大脑，外形在身体**。人格、音色、记忆属于大脑里的"角色"；视频、模型文件属于身体里的"外形包"。同一个角色可以换外形，记忆不丢。
5. **大脑断线时身体照样活着**：继续待机、能睡觉、能被拖动，只是不会说话。

## 2. 连接

### 2.1 传输方式：大脑自己开一个 WebSocket 服务

查过 dsh 0.2 的接口：插件能用的 `/api` 通道只支持普通请求（不能保持长连接）。dsh 的 web 版虽然有 `webServer.registerUpgrade` 可以接 WebSocket，但**桌面版 dsh 不走 HTTP**。所以：

- **大脑自己监听一个本地端口**（默认 `127.0.0.1:38100`，被占用就自动换一个），用 `ws`（dsh 本身就依赖它）。这样 dsh 网页版、桌面版、跑在 VPS 上都能用。
- 一条连接同时传两种东西：
  - **文字帧（JSON）**：控制消息。
  - **二进制帧**：音频。格式是一个 4 字节头（媒体流编号 + 序号）加数据。

### 2.2 怎么找到大脑、怎么认证

| 场景 | 做法 |
|---|---|
| **本机，由插件拉起身体**（默认） | 插件启动身体程序时，通过环境变量传入 `DSH_HER_URL` 和 `DSH_HER_TOKEN`。用户无感 |
| **本机，身体是用户自己打开的** | 身体先读一个约定位置的发现文件 `~/.dsh-her/brain.json`（含地址和令牌，权限 600）|
| **大脑在 VPS，身体在本机** | dsh 页面显示一个 6 位配对码（5 分钟有效）→ 在身体里输入 → 换到一个长期令牌，存进系统钥匙串（和小秘书的做法一样）。远程连接必须走 `wss`（加密），可以复用 dsh-vps 里的 caddy |

令牌放在连接的第一条消息里，不放在 URL 上，避免进日志。

### 2.3 心跳、重连、版本

- 每 15 秒心跳一次，连续 3 次没回应就算断线。
- 身体断线重连：1 秒起步，每次加倍，最长 30 秒，加随机抖动。重连成功后，大脑会把当前状态完整推一遍（快照）。
- 握手时双方报协议版本 `v`：大版本不同就拒绝并提示升级；小版本只做加法，**不认识的消息类型直接忽略**。

## 3. 握手

### 身体 → 大脑：`hello`

```json
{
  "t": "hello", "v": 1, "token": "…",
  "body": { "kind": "video", "app": "dsh-her-body", "version": "0.1.0", "os": "darwin" },
  "caps": {
    "audioOut": ["opus", "mp3", "wav"],
    "micIn": { "formats": ["pcm16@16k", "opus"], "vad": "silero" },
    "asrLocal": false,
    "ttsLocal": ["say"],
    "modes": ["wallpaper", "overlay", "window"],
    "screens": [{ "id": 1, "w": 2560, "h": 1600, "scale": 2 }]
  },
  "packs": [
    {
      "packId": "su-overlay-v1", "kind": "video", "name": "苏 · 桌宠",
      "states": ["idle", "listen", "think", "talk", "sleep"],
      "emotions": ["happy", "shy"],
      "actions": [
        { "id": "wave", "desc": "挥手打招呼" },
        { "id": "outfit_jk", "desc": "离开去换 JK 再回来展示", "durationMs": 14000 },
        { "id": "line_morning", "desc": "说早安", "hasAudio": true, "transcript": "早呀，今天也要元气满满哦。" }
      ],
      "hitParts": ["head", "body"]
    }
  ]
}
```

### 大脑 → 身体：`welcome`

```json
{
  "t": "welcome", "v": 1, "sessionId": "…",
  "characters": [
    { "cid": "su", "name": "苏", "packId": "su-overlay-v1", "mode": "overlay", "subtitle": { "color": "#cbb6ff" } }
  ],
  "config": { "mic": "push-to-talk", "bargeIn": true }
}
```

拿到 `packs[].actions` 后，大脑把它们变成大模型可以调用的工具 `play_action`：用一个枚举列出可选动作，`desc` 就是给模型看的说明。

## 4. 消息总表

除 `hello` 和 `welcome` 外，每条消息都带：`t`（类型）、`cid`（哪个角色，用于多角色）、`id`（需要回执时才带）。

### 大脑 → 身体

| `t` | 字段 | 作用 |
|---|---|---|
| `character.load` / `character.unload` | `cid, packId, name, mode, subtitle` | 让某个角色出现或消失 |
| `state` | `state: idle\|listen\|think\|talk\|sleep` | 改状态。`talk` 一般不用手动发，播放语音时身体会自动进入 |
| `emotion` | `emotion, intensity?` | 情绪。没有对应素材时身体自己降级 |
| `speak.begin` | `uid, emotion?` | 新的一轮回复开始（`uid` 是这轮回复的编号） |
| `speak.seg` | `uid, seq, text, durationMs, marks?` + 紧跟一个二进制音频帧 | 一句话：文字 + 音频。`marks` 是每个字的时间点（有就给，没有身体就按时长平均分） |
| `speak.end` | `uid` | 这轮回复的句子发完了 |
| `speak.cancel` | `uid` | 大脑主动取消（比如你在输入框里又打了字） |
| `act` | `id, action, args?` | 播放动作或储备台词，需要回执 |
| `bubble` | `text, ttlMs?` | 不出声的文字气泡（静音模式、提示） |
| `ask` | `id, question, options[]` | 需要你确认（比如 dsh 工具审批）。她会说出问题，身体显示按钮，你也可以用语音回答 |
| `mode` | `mode, screen?, pos?, scale?` | 切换壁纸层 / 最上层 / 普通窗口，或改位置 |
| `config` | 部分字段 | 热更新设置（麦克风开关、打断开关……） |

### 身体 → 大脑

| `t` | 字段 | 作用 |
|---|---|---|
| `user.text` | `text` | 你在输入框打的字 |
| `user.utterance` | `uttId, format, durationMs` + 二进制帧；或者 `text`（身体自己识别时） | 你说了一句话 |
| `user.speechStart` | | 你开口了。如果她正在说，身体已经在本地停下了 |
| `interrupt` | `uid, seq, playedMs` | 她的话被打断在哪里。大脑据此停掉生成和合成，并**在记忆里记成"她只说到这里"** |
| `speak.progress` | `uid, seq, phase: start\|end` | 每句开始和结束播放的时刻，导演据此知道她什么时候说完 |
| `act.done` | `id, ok, reason?` | 动作播完、失败或被打断 |
| `answer` | `id, option \| text` | 对 `ask` 的回答 |
| `touch` | `part, kind: tap\|double\|long` | 点了她哪里 |
| `drag` | `phase, pos` | 被拖动（拖完可以说一句"放我下来啦"） |
| `presence` | `active\|idle\|away, fullscreen, locked` | 你在不在电脑前，粗粒度，**不含任何内容** |
| `posture` | `anchor` | 视频外形当前在哪个锚点（坐 / 站 / 不在画面）。导演用来判断"现在能不能直接说话" |
| `mode.changed` | `mode, pos` | 你手动改了窗口模式或位置，大脑保存为偏好 |
| `error` | `code, message` | 素材坏了、播放失败等 |

## 5. 关键流程

### 5.1 一轮语音对话

```
你开口 ──► 身体 VAD：user.speechStart（她切到"倾听"）
你说完 ──► 身体：user.utterance + 音频 ──► 大脑 识别成文字
                                       ──► state: think（她切到"思考"，掩盖等待）
                                       ──► 对话（流式）→ 切句 → 合成
        身体 ◄── speak.begin / speak.seg #1（文字+音频）
        身体：播放 #1，循环播说话片段，字幕逐字出现 ──► speak.progress #1 start
        身体 ◄── speak.seg #2 …（先进队列，边播边收）
        身体 ◄── speak.end ── 最后一句播完 ──► speak.progress end ──► 回到待机
```

### 5.2 打断

```
她正在说 #2 ──► 你开口 ──► 身体：立即本地停止播放、清空队列（不等大脑）
                       ──► interrupt{uid, seq:2, playedMs:1300} + user.speechStart
大脑：停止生成、停止合成；记忆里记成"她说到第 2 句的一部分就被打断了"
之后按 5.1 正常进行
```

### 5.3 "想看 JK"

```
你说"想看 JK" ──► 大脑：模型调用 play_action("outfit_jk")
              ──► act{id:7, action:"outfit_jk"}
身体：在姿势图上找路径（坐 → 起身 → 走出右边 → 换装后走回来 → 展示）
     途中 posture 变化逐个上报 ──► act.done{id:7, ok:true}
大脑：接着说"怎么样？"（speak…）
```

如果动作还没播完你就说话了：身体判断这段能不能中途停。"离开画面"这种不能停的，播完再处理；能停的直接打断，回 `act.done{ok:false, reason:"interrupted"}`。

### 5.4 储备台词

```
早上你第一次动鼠标 ──► 身体 presence:active ──► 大脑判断"今天还没打招呼"
                 ──► act{action:"line_morning"}（片段自带声音，口型精确）
大脑把这句台词的文字写进记忆，当作她说过的话
```

### 5.5 大脑掉线（dsh 被关掉）

身体继续待机；过一段时间切到"睡觉"状态；托盘提示"她在等 dsh"；按退避规则重连。重连后收到 `welcome` 和状态快照，恢复正常。

## 6. 音频

- **由大脑合成**（默认）。理由：
  - 音色配置和 API 密钥只在一个地方。
  - 多个身体可以共用同一个声音。
  - 大脑天然知道每句话的文字和时长。
  - 远程场景下，24kbps 的 Opus 带宽完全够用。
- **以句为单位**：每句是一段完整的音频（Opus / MP3 / WAV，按 `caps.audioOut` 协商），不做逐个采样点的流式传输。实现简单，句与句之间也自然形成停顿。
- **麦克风**：身体本地做 VAD 判断你说完了，再把整句上传（16k 采样的 PCM16 或 Opus）。流式识别（边说边出字）以后作为可选能力加入。
- **口型**：身体按正在播放的音频音量实时计算嘴张开多少。不走协议，零延迟。视频外形可以忽略这个值。
- **防止旧回复重播**：身体只播 `speak.begin` 之后收到的句子。重连后的状态快照里不包含历史音频。

## 7. 形象接口（身体内部，交互层 ↔ 外形）

交互层只认这个接口，不关心背后是视频、图片、Live2D、VRM 还是 Unity：

```ts
interface Avatar {
  readonly caps: AvatarCaps            // 状态、情绪、动作、能否控制嘴型、可点击的部位
  mount(surface: Surface): Promise<void>
  setState(state: AvatarState): void   // idle | listen | think | talk | sleep
  setEmotion(e: Emotion, intensity?: number): void
  play(action: string, args?: unknown, signal?: AbortSignal): Promise<ActResult>
  setMouth?(level: number): void       // 0–1，视频外形可以不实现
  hitTest(x: number, y: number): HitPart | null   // 点击穿透和"点她"都用它
  onPosture?(cb: (anchor: string) => void): void
  dispose(): void
}
```

**视频外形的实现方式**：
- 维护姿势图（锚点 = 节点，片段 = 边）。`setState` 和 `play` 都转化成在图上找路径。
- 用两层 `<video>`：锚点对齐的片段直接硬切；没对齐的交叉淡化 0.8 秒兜底（借鉴同类项目）。
- `hitTest` 读当前帧对应位置的透明度。

**降级规则**（由交互层统一处理）：
- 没有 `think` 片段 → 用 `listen` 代替；再没有就用 `idle`。
- 没有某个情绪 → 用 `happy` 或保持中性。
- 没有某个动作 → 回 `act.done{ok:false, reason:"unsupported"}`，大脑改为用说话代替。

## 8. 多角色

- **一个身体程序，一条连接，多个窗口**。每条消息都带 `cid` 区分角色。
- 麦克风只有一个：身体只上报一次你说的话，由大脑里的导演决定谁来回答（你叫了谁的名字；没叫名字就由最近说过话的那个回答）。
- 同一时刻只让一个角色出声。另一个可以做"倾听"状态或者小动作。

---

## 9. 隐私与安全

- 默认只监听本机 `127.0.0.1`，必须有令牌才能连。开放远程连接需要手动打开，并且必须加密。
- 麦克风：只在开启后、并且 VAD 判断有人说话时才上传；麦克风开着时身体显示指示灯。
- `presence` 只报"活跃 / 空闲 / 离开 / 全屏 / 锁屏"，不报窗口标题，也不报屏幕内容。屏幕感知以后作为单独的、默认关闭的能力。
- 令牌存在系统钥匙串里，不写进普通文件（本机发现文件除外，权限 600）。

## 10. 延迟预算（从你说完到她开口）

| 环节 | 目标 |
|---|---|
| 判断你说完了（静音时长） | 0.6–0.8 秒。同类项目用 1.8 秒，太慢；做成可调 |
| 语音识别 | 0.3 秒 |
| 对话生成第一句 | 0.8–1.5 秒 |
| 合成第一句 | 0.3–0.8 秒 |
| **合计** | **约 2–3 秒**。等待期间她处于"思考"状态，看起来自然 |

## 11. 已定事项的细节

1. **她的对话放在哪里**：用方案 (a)，每个角色在 dsh 里有一个专属的长期会话。她能用 dsh 的工具和审批，对话记录在 dsh 网页里也看得到。落地细节见 `docs/大脑与dsh会话.md`。
2. **端口**：首选 38100，被占用就向后找一个可用端口。实际端口和令牌写进发现文件 `~/.dsh-her/brain.json`（权限 600），插件拉起身体时也通过环境变量传过去。
3. **打断**：默认插话模式。身体开启回声消除（Chromium 的 `echoCancellation`），只用 VAD 判断你有没有开口。如果检测到她自己的声音反复触发打断（比如 30 秒内误触发超过 2 次），就自动切到排队模式，并提示你"外放回声太大，已改为说完再听，戴耳机效果更好"。
4. **片段能否中途打断**：外形包里每个片段带 `interruptible: true|false`，默认 `true`。进出画面、换装这类片段标成 `false`。

## 她先开口和碰她（docs/主动与触摸设计.md）

- `presence`：身体每 30 秒报告你在不在（`active` / `idle` / `away`）。3 分钟没报告就算不知道，她不会开口。`fullscreen` 现在总是 false（Electron 看不出别的程序全屏）。
- `touch`：`part` 是 `head` 或 `body`，`kind` 是 `tap` 或 `long`。身体先自己动，再发这条。`double` 不再发送，双击是打开输入框。
- `focus.set`：身体菜单的"专注一会儿"，开启时是 2 小时。
- `welcome.config.focus` 和 `config.focus`：大脑告诉身体现在是否专注，给菜单打勾用。

## 对话小条（docs/对话入口设计.md）

- 大脑发 `talk`：她的名字、最近几句、当前这段和之前的几段、这段有多长。身体连上、她说完一句、换了一段时都会发。
- 身体发 `talk.get`（要一次）、`talk.new`（新开一段）、`talk.resume`（接着之前那段）、`talk.open`（在 dsh 里看完整对话：下一个来问状态的 dsh 页面打开这段）。
- 按住说话在身体内部：小条窗口把"按住/松开"交给她的窗口（麦克风在那里），松开后照常发 `user.utterance`。
