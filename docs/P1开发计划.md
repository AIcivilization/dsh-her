# dsh-her P1 开发计划

> P1 目标：**视频版桌面女友**。她站在 mac / Windows 的真实桌面上（最上层或壁纸里），能实时语音聊天、有记忆、会做动作和储备台词；素材由用户自己导入；7 步向导，3 分钟内装好。
> P1 **不包括**：干活（操作电脑）、灵魂引擎、小秘书联动、3D 外形、多角色、一张照片生成素材。

## 1. 仓库结构

沿用小秘书的写法：根目录就是插件包（npm 包名 `dsh-her`），身体程序放在子目录。

```
dsh-her/
├─ package.json            插件包（dsh-her），TypeScript strict，node:test
├─ cordis.patch.yml
├─ src/
│  ├─ core/                与 dsh 无关的纯逻辑：切句、行内标记解析、记忆、导演、语音合成/识别接口
│  ├─ dsh/                 dsh 适配层：插件入口、专属会话、生成流、配置（dsh 接口变化只改这里）
│  ├─ server/              身体协议的 WebSocket 服务、配对、发现文件
│  ├─ voice/               语音子进程（sherpa-onnx）与云端引擎
│  └─ client/              dsh 网页里"她"这一页：向导 + 管理页（React，和小秘书一样）
├─ shared/protocol/        协议消息类型与校验，插件和身体共用同一份源码
├─ body/                   Electron 身体（独立的 package.json，electron-builder 打包）
│  ├─ main/                窗口模式、壁纸层（mac 用 desktop 类型窗口 / Windows 用 WorkerW）、托盘、快捷键、导入处理
│  ├─ renderer/            外形接口、视频外形、姿势图、交互层、VAD、播放、字幕
│  └─ native/              koffi 调用 user32 的代码（只在 Windows 用）
├─ tests/
└─ docs/
```

**协议补充**：导入素材需要在身体这一侧打开文件夹选择框（大脑可能在 VPS 上，碰不到你的文件），所以协议加几条消息：`pack.pick`、`pack.import`、`pack.progress`、`pack.report`、`pack.list`。向导在 dsh 网页里发起，在你的桌面上弹出文件夹选择框，进度和报告再传回网页显示。

## 2. 里程碑

> 时长是**粗估**（一人加我配合），每个里程碑做完都有可以亲眼看到的演示。

### M0 骨架与三个风险验证（约 1–1.5 周）

先把最可能翻车的三件事各做一个最小验证，再往下做。

| 验证 | 要证明什么 | 通过标准 |
|---|---|---|
| **A. Electron 身体** | 透明窗口、按遮罩点击穿透、播放 VP9 透明视频；mac 用 `type:'desktop'` 进壁纸层；Windows 10 和 Windows 11 24H2 都能用 WorkerW 进壁纸层 | 三种模式都能看到她；最上层模式点她有反应、点空白处能穿透到桌面；**Apple Silicon 上待机 CPU 低于 3%**（实测记录） |
| **B. 本地语音** | `sherpa-onnx-node` 能在 dsh 插件里运行（单独开一个语音子进程，带正确的动态库路径），SenseVoice 能识别、Kokoro 能合成 | mac arm64 和 Windows x64 上，识别一句 5 秒的话在 0.5 秒内完成；合成首句在 0.8 秒内完成 |
| **C. dsh 专属会话** | 照 dsh-vael 的写法建出"她 · 示例"会话；整段替换系统提示词；监听生成流逐字拿到文字；`cancel` 能打断 | 在 dsh 网页里能看到这个会话，打字后插件日志里逐字打印回复，打断后会话里留下带 `interrupted` 标记的消息 |

同时完成：仓库骨架、`shared/protocol` v1 的类型定义、CI（类型检查 + 测试）。

### M1 大脑与身体打通（文字）（约 1 周）

- 大脑：WebSocket 服务（端口冲突时自动换端口）、发现文件、令牌、心跳、断线重连、状态快照。
- 插件拉起身体时通过环境变量传地址和令牌；身体自己打开时读发现文件。
- 身体：输入框打字 → 她的专属会话 → 回复以字幕气泡显示。**在 dsh 网页里打字，桌面上同样显示。**
- 外形先用开发素材，只做待机和"说话中"两种状态。
- **验收**：关掉 dsh 再打开，身体自动重连，她不会把旧回复再显示一遍。

### M2 语音（约 1.5–2 周）

- 大脑：边生成边切句 → 清理文字 → 合成 → `speak.*` 消息；启动预热；常用短句缓存。
- 身体：按句排队播放；字幕逐字出现；按住快捷键说话；silero VAD；回声消除。
- **打断**：身体本地立刻停 → `interrupt` → 大脑 `cancel` → 下一轮附上"她说到哪里被打断了"。
- 误打断太多时自动退回排队模式。
- 云端合成：阿里云 CosyVoice，包括克隆音色。
- **验收**：从你说完到她开口，**中位数 3 秒以内**（实测记录）；外放和戴耳机两种情况各测 20 轮打断。

### M3 外形包与姿势图（约 2 周）

- 导入检查：认文件名 → 查规格 → SSIM 比对接缝 → 抠绿幕转"上下叠放的 H.264" → 生成点击遮罩 → 报告（使用打包进身体的 ffmpeg）。
- 姿势图运行时：片段池、寻路、硬切 / 交叉淡化、`interruptible`、换装、组合动作、储备台词。
- 行内标记 `〔开心〕`、`〔动作:wave〕` 的解析；`play_action` 工具；系统提示词里的表演段落根据外形包自动生成。
- 场景包：把空场景图设成系统壁纸，视频放在壁纸层播放。
- **验收**：用你生成的第一套素材，完整演一遍"想看 JK"：起身 → 离开 → 换装后回来 → 展示 → 说话。全程没有闪烁和跳帧，中途说话能按规则打断。

### M4 内置记忆（约 1 周）

- 关于你 / 日记 / 事件三层存储；`remember` / `recall` 工具。
- 每天整理一次；候选事实 7 天后自动确认（敏感内容除外）；带日期的事到期主动提起。
- "她记得的事"页面：查看、修改、删除、导出、清空；语音"忘掉这件事"。
- **验收**：告诉她三件事，重启电脑、隔一天，她都能自然地提起；删掉其中一条后她不再提。

### M5 向导与管理页（约 1.5 周）

- dsh 左侧栏"她"页面：7 步向导，完成后变成管理页。
- 身体的下载、校验、安装、更新；托盘菜单；设置（快捷键、模式、麦克风、音量……）。
- **验收**：找一个**没看过这些文档的人**，在一台干净的 mac 和一台干净的 Windows 上，不靠任何人帮忙，3 分钟内让她站到桌面上并说上话。

### M6 打磨与发布（约 1–1.5 周）

- 省电（全屏、锁屏、被挡住时暂停；用电池时降帧）、多显示器、屏幕缩放。
- mac 签名并公证；Windows 安装包。
- 中英双语 README、常见问题；**换上官方示例外形包**。
- 发布 v0.1.0：npm 插件 + GitHub Releases 上的身体程序。

**合计约 9–11 周。** M0 结束后再校准一次。

## 4. 风险与应对

| 风险 | 可能性 | 应对 |
|---|---|---|
| `sherpa-onnx-node` 原生模块在 dsh 进程里加载失败（动态库路径、架构不匹配） | 中 | 语音放在**独立子进程**里运行，由插件设置好环境变量再拉起；M0 先验证。实在不行，本地引擎改由身体程序负责 |
| Windows 壁纸层（WorkerW）在某些版本上挂不上 | 中 | 两个 Windows 版本都在 M0 验证；挂载失败自动退回"最上层贴屏幕底部"，并在托盘里说明原因 |
| dsh 0.2 还在 rc 阶段，接口可能变 | 高 | dsh 调用全部集中在 `src/dsh/`；`package.json` 写明支持的 dsh 版本范围；跟进 dsh 发版 |
| 素材接缝差，看起来有跳帧 | 中 | 导入检查给出分数和建议；交叉淡化兜底；提示词里强调首尾帧 |
| 开口太慢 | 中 | 每个里程碑都记录延迟；快速模型、预热、短句缓存、思考片段掩盖等待 |
| Electron 待机太耗电 | 低–中 | M0 就实测；降帧、暂停、静帧 |

## 5. 开发约定

- TypeScript strict；测试用 `node:test`；协议消息在运行时做校验。
- 不收集任何使用数据；API key 存进系统钥匙串。
- 同类项目的素材只放在本地开发目录（`~/dsh-her-dev-assets/`），**不进仓库**。
- 每个里程碑结束：更新 README 的进度、记录实测数据、录一段演示视频。
