## C. dsh 专属会话 —— ✅ 通过

做法照抄 dsh-vael：在 `agents.create/resume` 的 `setup` 里整段替换系统提示词、隐藏 DSH 自带的工具、监听 `agent/assistant-stream`。代码在 `src/dsh/her-session.ts`。

| 检查项 | 结果 |
|---|---|
| 建会话、重启后恢复同一个会话 | ✅ 会话 id 记在 `~/.dsh-her-dev/characters/sample/session.json`，dsh 侧栏里显示"她 · 小禾" |
| 只在她的会话里替换系统提示词 | ✅ 回复完全是人设口吻（"那我更不想起床了，正窝在被子里听雨声呢。"） |
| 逐字拿到生成流，按句切开 | ✅ 一段回复切成 3 句，按顺序到达 |
| 第一句的时间 | 发出后约 **2.0–2.9 秒**（模型：WorkBuddy DeepSeek-V4.1-Flash，思考强度 High，该路由不能关思考） |
| 隐藏 DSH 自带的工具 | ✅ 每轮输入从约 **8.4K token 降到约 1.4K**（其中 1.15K 走缓存）。用 `tools.restrict({ deny })` 实现 |
| 打断 | ✅ 第一句之后调 `cancel`，**7 ms** 停稳；dsh 记下 `assistant/message.interrupted = true`，只保留已经生成的前半段 |
| 她知道自己被打断过 | ✅ 下一轮她主动说"是不是刚才我故事还没开始讲，你就先睡着了？" |

**注意**：dsh 的会话存储是全局的（`~/.dsh/sessions`），测试 profile 建出来的"她 · 小禾"会话，在你的桌面版 dsh 里也看得到。

**要带进 M1/M2 的结论**：
- 要找一个能关思考、或者思考强度低的快速模型给她用。配置项 `reasoningEffort` 已经加好。
- dsh 网页在她的会话被插件驱动时偶尔不刷新显示，需要在 M1 复查。

## B. 本地语音（sherpa-onnx）—— ✅ 通过（mac）；Windows 待测

语音在独立子进程里运行（`src/voice/worker.ts`），主进程侧是 `src/voice/engine.ts`，测速脚本是 `npm run voice:bench`。

| 检查项 | 结果 |
|---|---|
| 在 DSH 桌面版的 Electron 运行时里加载原生模块 | ✅ DSH.app 的签名带 `disable-library-validation`，可以加载 |
| Electron 下合成报错"External buffers are not allowed" | ✅ 已修：合成时传 `enableExternalBuffer: false` |
| 模型加载 | 1.3 秒（Node）/ 1.7 秒（Electron） |
| **识别**（SenseVoice int8） | 5.6 秒录音 → **87–129 ms**；把她自己合成的话识别回来 52–65 ms ✅ |
| **合成**（Kokoro v1.1） | int8 版：一句 1.7–2.6 秒（实时率约 0.84）❌ → 改用 **fp32 版 + 4 线程：一句 0.68–1.06 秒（实时率约 0.35）** |

**结论**：
- 合成默认用 fp32 版（下载 365 MB，比 int8 版的 147 MB 大，但快一倍多）。
- 实时率 0.35，意味着第二句以后合成都比播放快，不会卡。
- **第一句还略高于 0.8 秒的目标**。M2 用两个办法压下来：第一句在逗号处提前切成短句；常用短句预先缓存。
- 语言标签对中文录音给出了 `yue`（粤语），文字本身是对的；以后不依赖这个标签。
- 音色样本在 `~/.dsh-her-dev/logs/voice-bench/voice-sid*.wav`，共 103 个音色，待你挑默认音色。

### 透明视频格式：改用"上下叠放的 H.264"

| 格式 | 解码 | 播放时 CPU（单核口径，M1 Pro） |
|---|---|---|
| VP9 带透明通道（WebM） | mac 上只能软解 | **30.6%**（峰值 51%） |
| **H.264 上半彩色、下半透明遮罩，WebGL 合成** | 硬件解码 | **约 17–18%**（峰值 28%） |
| 普通 H.264、不透明（对照） | 硬件解码 | 11.4% |
| 暂停在一帧上 | — | **0.4%** |

- 把宽度从 480 降到 360 几乎不省（16.7%），说明开销主要在"每一帧都要合成一次透明窗口"，而不在解码。
- 屏幕截图和页面像素逐点比对过（不透明度 254 → 屏幕 255），合成是对的。
- 这套开发素材看着发虚，是角色本身的玻璃质感皮肤，加上抠黑底造成的；正式素材用绿幕，不会这样。

**结论**：
1. 导入处理统一输出"上下叠放的 H.264"，不再用 VP9 透明视频（改了 `docs/外形包与姿势图.md`）。
2. "待机 CPU 低于 3%"按活动监视器的单核口径算，**持续播放做不到**（约 17%，折合整机 10 核约 1.7%）。所以省电策略升级为 P1 必做：
   - 有互动、正在说话时：正常播放。
   - 一段时间（默认 2 分钟）没有互动：每 20–40 秒播一段待机片段，其余时间停在一帧上，**平均预计降到 2–4%**。
   - 全屏程序、锁屏、被完全挡住时：暂停（0.4%）。
3. 开发素材的元数据里写着它们是用 Wan 的"首尾帧生视频"做的，印证了提示词文档的思路。转换时已经去掉原文件的元数据。
