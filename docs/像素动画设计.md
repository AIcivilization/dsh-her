# 像素动画和像素模版

2026-11-20。要加三件事（已经做了，做法和下面不一样的地方见文末「实际做法」）：

1. **像素动画当开机动画**：作为开机动画的一种，和视频并列。
2. **像素动画当 dsh 背景动画**：画在 dsh 对话窗口后面，像 DSH 首页那只跃出的鲸鱼。
3. **第六套模版「像素」**：人物形象和动画都是像素风。

1 和 2 是同一个东西：一份**像素动画**（一个代码文件），用在两个地方。3 是另一件事，和素材指南、形象有关。

---

## 1. 先看 DSH 那只鲸鱼是怎么做的

源码在桌面版里的 `@deepseek-ai/dsh-client-ui-brand-official/src/client/home-whale/`，要点：

- 动作存在一张帧图里：137 帧拼成一张 2304×1296 的 webp，每帧 192×108，只有 189KB。
- 帧图存的是数据，不是画面：红色通道是点的大小，绿色通道是透明度。
- 播放时用 Canvas 每秒画 24 帧。同一份动作有两种画法：**圆点**（每格画一个圆），和**代码字**（铺一层小字，用当前帧当蒙版裁剪）。
- 颜色从主题里读，整体透明度 0.18，压在对话内容下面，不挡点击。
- 窗口在后台、看不见，或系统开了「减少动态效果」，都会停。

我们学的是方法：**动作是一张粗格子，画法和颜色由引擎决定**。DSH 的帧图和代码我们一个都不拿。

---

## 2. 像素动画是什么

**一个像素动画 = 一个 `.js` 文件。**它只管一件事：每一帧，往一张粗格子（比如 192×108）里填数。

怎么把格子画到屏幕上，由引擎负责，用户在设置页里选：

| 画法 | 样子 |
|---|---|
| 方块 | 清晰的像素方块，经典像素风 |
| 圆点 | 每格一个圆，越亮越大，就是 DSH 鲸鱼的点阵 |
| 代码字 | 格子当蒙版，透出密排的小字，就是 DSH 鲸鱼的代码填充 |

这样分开，好处有三个：
- 写代码的人（或大模型）只要想动作，不用管清晰度、屏幕大小、深浅色主题。
- 同一份动画，用户能自己换画法、换颜色。
- 格子很小（最大 384×216），每帧计算量小，启动快。

格子有两种：
- **单色**：每格只给亮度（0–1），颜色跟着 dsh 主题，或者由用户在设置里选。三种画法都能用。
- **彩色**：每格给自己的颜色，只能用「方块」画法。

## 3. 代码格式（给大模型看的规格）

设置页里有一段「给大模型的说明」，一键复制。用户贴给 DeepSeek、ChatGPT，或者直接贴进 dsh 对话框，说想要什么动画，让它写好，再把文件传上来。下面就是那段说明的核心内容。

```js
// dsh-her 像素动画 @1：一个文件，不 import 别的东西
export const info = {
  name: '浪花',            // 显示的名字
  author: '',              // 可选
  grid: [192, 108],        // 宽 × 高，单位是格；最大 384 × 216
  fps: 24,                 // 每秒几帧，1–30
  seconds: 4,              // 一遍多长；开机动画最长 8 秒；0 = 一直循环（只能当背景）
  color: 'mono',           // 'mono'：每格只给亮度；'color'：每格自己给颜色
}

// 可选：开始前调一次，用来准备数据
export function setup(g) {}

// 每帧调一次：t 是秒（0 开始），n 是第几帧
export function frame(g, t, n) {
  g.clear()
  // 在这里填格子
}
```

`g` 能用的东西（全部同步执行，没有网络，也没有页面）：

| 名字 | 作用 |
|---|---|
| `g.w`、`g.h` | 格子的宽和高 |
| `g.clear()` | 全部清空 |
| `g.set(x, y, v, a = 1)` | 单色：亮度 v、透明度 a，都是 0–1 |
| `g.rgb(x, y, r, gr, b, a = 1)` | 彩色：0–255，a 是 0–1 |
| `g.rect`、`g.circle`、`g.line` | 画方块、圆、线（单色用 v，彩色用颜色） |
| `g.text(x, y, '字', v)` | 5×7 像素字体，只有英文、数字和常用符号 |
| `g.random()` | 固定种子的随机数，每次播放结果一样 |
| `g.noise(x, y, z)` | 平滑噪声，用来做水、云、火 |
| `g.ease.inOut(p)` 等 | 常用缓动 |
| `g.data` | 直接写的底层数组（追求速度时用） |

规矩，也写在说明里：
- 只有一个文件，不 `import`，不用 `fetch`，也不碰 `document`、`window`（这些本来就用不了）。
- 每帧计算要在 8 毫秒以内。文件大小不限（2026-11-21 起，见 [像素导出设计](像素导出设计.md) §8）；当开机动画建议 200 KB 以内。
- 开机动画要在 `seconds` 里播完，结尾自己淡出；背景动画如果循环，首尾要接得上。

说明后面附一个大约 40 行的完整例子（浪花），让大模型照着写。

## 4. 安全：用户上传的代码在哪里跑

上传的代码是大模型写的，也可能是网上找来的。在 dsh 页面里，能调 dsh 的接口就能动用户的会话、文件，甚至命令行，所以**绝不能在 dsh 页面里直接跑**。

做法是隔两层：

1. **沙盒 iframe**：`sandbox="allow-scripts"`，不给 `allow-same-origin`。代码拿不到 dsh 页面、cookie 和本地存储，算是另一个「陌生网站」。
2. **iframe 里设内容安全策略**：`default-src 'none'`，只允许内联脚本和 blob。这样它连网都连不上，也不能往 dsh 的接口发请求。
3. **代码放在 iframe 里的 Worker 线程里跑**：Worker 算出格子交给 iframe，由 iframe 画出来。代码写成死循环也卡不住界面：一帧超过 200 毫秒没回来，就结束 Worker，动画停掉，并提示「这个动画太慢，已停止」。

dsh 页面和 iframe 之间只传几样东西：开始、停止、尺寸、颜色、画法。iframe 不接收用户输入，`pointer-events:none`。

桌面上的开机动画窗口（Electron）也一样：窗口开 `sandbox`，不加载 preload，不开 Node，页面里还是同一个沙盒 iframe 加 Worker。

我们不对代码做「检查它安不安全」这种静态扫描，那样靠不住。安全全靠隔离。

## 5. 上传和检查

- 入口：「像素动画」页的上传按钮。可以传 `.js`，也可以传 `.zip`（以后如果支持帧图，见 §10）。
- 传上来以后，引擎在沙盒里试跑：读 `info`，跑 `setup`，再跑开头、中间、结尾三帧，并计时。
- 有问题就用一句人话说出来，并附上原始报错，旁边一个「复制给大模型」按钮。比如：
  - `info.grid 写成了 [800, 600]，最大 384 × 216`
  - `frame 第 12 帧出错：g.fil is not a function`
  - `每帧要 31 毫秒，太慢（要在 8 毫秒以内）`
- 没问题就生成一张缩略图（中间那帧），放进列表。
- 存放：`<home>/pixels/<id>/`，里面是 `anim.js` 加一份 `meta.json`（名字、上传时间、试跑结果）。所有人物共用，和素材库、皮肤一样。

## 6. 用处一：开机动画

现在开机动画的来源是「皮肤自带」或「素材库里的一段视频」。现在加第三种：**像素动画**。

- 设置：皮肤页的「开机动画」选择里，多一组「像素动画」。另外的设置照旧：开关、每次都播还是每天第一次、点一下跳过。
- 像素动画自己的设置跟着这个选择走：画法、颜色、大小（占屏幕多少）。
- 在哪播：
  - 桌面：现在的开机动画窗口（透明、置顶、不抢焦点），里面换成像素播放页。
  - dsh 页面：现在的半透明遮罩，里面换成沙盒 iframe。
- 时长：照 `info.seconds`，最长 8 秒，到时间强制结束；`seconds: 0` 的循环动画不能选作开机动画。

`IntroSettings.source` 现在是 `'skin'` 或一个素材名，多一种写法 `pixel:<id>`。旧设置不用改。

## 7. 用处二：dsh 背景动画

画在 dsh 对话窗口后面，对话内容照常叠在上面。

- **在哪层**：一个铺满整个页面的固定层，在皮肤背景图上面，在所有内容下面，不接收点击。这样不依赖 DSH 的插槽，桌面版和网页版都能用。
- **怎么动**，用户三选一：
  - 点一下页面空白处，播一遍（默认，和 DSH 的鲸鱼一样）
  - 一直循环
  - 每隔几分钟播一遍
- **调节**：画法、颜色（跟主题，或选一个色）、透明度（默认 0.15）、大小和位置（铺满，或者居中占多少）。
- **省电**：页面在后台或看不见就停；系统开了「减少动态效果」就不播；手机上默认不开；一直循环时帧率上限 15。
- **和 DSH 自己的鲸鱼**：DSH 首页的鲸鱼只在空白首页、点击时才出来。我们的层在它下面，两个可能同时出现。设置里提示一句就行，不去关掉 DSH 的鲸鱼（那是 DSH 的东西）。
- 背景是「dsh 的样子」，和皮肤一样属于共用设置，不跟着人物。

## 11. 第六套模版：像素

### 11.1 是谁

**推荐：像素鲸鱼娘。**她和另外三套鲸鱼娘是同一个人，换成像素画风；三样必有元素照旧（尾巴头饰、DeepSeek 鲸鱼标、蓝色鲸尾）。

理由：像素风最适合做桌宠，也最像「DSH 的」。真人女友、男友做成像素风意义不大。

### 11.2 提示词

在 `material-guide.ts` 的 TEMPLATES 里加 `pixel`，写法和另外五套一样：

- **画风（look）**：16-bit 像素画，清晰的方形像素边缘，有限调色板（不超过 32 色），没有抗锯齿、模糊或渐变噪点，纯色块加少量抖动，像 SNES 时代的角色立绘和场景。
- **身材**：像素画也要写清楚，比如约七头身、腿长、腰线高；结尾加「避免：……」，规矩和另外几套一样。
- **头像**：Q 版像素小人，约 32×48 格的比例。
- **场景**：像素海边小屋，窗外是像素海和像素星空。
- **开机画面**：像素浪花里鲸尾拍水。它可以直接用自带的「鲸尾出水」像素动画，不用做视频。
- 视频提示词加一句：「保持像素风，像素格子大小不变，不要平滑插帧」。

### 11.3 引擎要补的一件事：像素化显示

图生视频工具做像素风视频，常常会糊，格子会跳，边缘会被抗锯齿。光靠提示词管不住。

引擎补一个**像素化显示**开关，跟着人物走，选了像素模版就自动打开：
- 她的图片和视频先缩小到一个固定格子（比如高 96 格），再放大回来，关掉平滑（`image-rendering: pixelated`）。
- 不管工具出来的视频有多糊，屏幕上都是干净、对齐的像素格。
- 可选「限制颜色」：把颜色压到 32 色以内，像素风更正。

这样像素模版不用新的素材类型：照旧传图和视频，引擎负责让它们看起来是像素风。会画像素画的人（比如用 Aseprite）导出的 GIF、PNG 序列也能用，同样按格子放大。

## 14. 实际做法（和上面不一样的地方）

- **播放页不另开地址**：沙盒 iframe 用 `srcdoc`，播放页整个打进客户端代码里（`scripts/pixel-player.mjs` 生成，`__PIXEL_PLAYER_HTML__`）。DSH 页面没有自己的内容安全策略，播放页自带 `default-src 'none'`，连不了网。桌面的开机动画窗口用同一个页面（`body/dist/pixel.html`），代码由主进程 `executeJavaScript` 交给它。
- **用户的代码怎么跑**：去掉 `export`，包进一个函数，和 worker 运行时拼成一个 blob，开成 Worker（`src/core/pixel.ts` 的 `wrapPixelCode`）。报错的行号换算回用户文件自己的行号。
- **背景层放在哪**：DSH 对话列（`_centerCol`）里一个 `z-index:-1` 的层，列本身设 `isolation:isolate`；每秒检查一次，DSH 重画了就重新挂上。「dsh 回答完」看 DSH 的运行图标（`_runningIcon`）消失；「你发出消息」看输入框（`_composerSeat`）里按回车或点发送按钮。
- **颜色「跟着 dsh」**：背景用 `--dsw-alias-label-secondary`（代码字用 `label-primary`），开机动画用 `--dsw-alias-brand-primary`；桌面上没有主题，用浅海蓝。
- **设计包里来的像素动画**不在服务器上运行，先存下，列表打开时在页面的沙盒里试跑、生成缩略图。
- **像素化显示**跟着人物（`character.pixel`，多少格高），桌面身体和网页身体都画：普通视频用 2D canvas 缩小（`body/renderer/pixel-view.ts`），stacked 视频的 WebGL 画布直接缩到这个高度，再用 `image-rendering: pixelated` 放大。场景底图（plate）和对话框上的小头像还没有像素化。
- **桌面上的像素开机动画**要新的桌面程序（0.8.5）；旧的桌面程序收到会跳过，不会乱播。
- 设计包**导出**还不带像素动画（只能装进来）。

## 15. 背景层放进对话区，换掉 DSH 自己的鲸鱼（2026-11-21）

用户设好了对话背景，点空白处只出来 DSH 原版的鲸鱼出水，我们的没出来。

- **原因**：背景层原来挂在对话栏（`_centerCol`）里，`z-index:-1`。但 DSH 的对话区（`ConversationRoot`，class 是 `…_root`，带 `data-phase`）自己铺了一层不透明的底色（`background: var(--dsw-alias-bg-base)`），正好盖在我们的层上面：动画其实在播，只是被挡住了，什么时候都看不见（之前"设了背景也没出现"也是这个）。DSH 的鲸鱼是画在对话区里面的，所以看得见。
- **改成**：背景层挂进对话区里（`[class*="_root"][data-phase]`，class 是哈希，`data-phase` 不是），给它设 `isolation:isolate`，`-1` 就落在它的底色上面、内容下面，和 DSH 的鲸鱼同一个位置。没有对话区的页面（她自己的页面）还挂在对话栏里。
- DSH 每打开一个对话都会画一个新的对话区：换了就在新的那里**新建**一层，不去挪旧的（挪 iframe 会让它重新加载，正在播的会卡住）。
- **我们的背景开着时，藏起 DSH 的鲸鱼**（`[data-home-whale]{visibility:hidden}`，一段带 `data-dsh-her` 的 style），点空白处出来的是我们的；关掉背景就去掉这段，DSH 的鲸鱼回来。这和 §7 原来说的"不去关掉 DSH 的鲸鱼"相反，是用户要的。
- 试过：照着 DSH 的结构和样式（对话栏 → 带底色的对话区 → 鲸鱼画布 → 内容）搭了一个测试页。旧位置放一块蓝色，看不见；新位置看得见。点空白处出来我们的浪花，DSH 的鲸鱼藏着；换一个对话以后再点，照样出来；关掉背景，DSH 的鲸鱼回来。没在真的 DSH 里点过。
