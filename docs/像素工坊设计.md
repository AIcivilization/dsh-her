# 像素工坊

2026-11-21 定的方向。四步都已经做了（见文末各步的「实际做法」）。像素动画本身的格式和播放见 [像素动画设计](像素动画设计.md)。

**目的**：不会写代码的人，也能做出自己要的像素动画。办法有两个：
- 和 AI 说"做一个……"，看着预览一句一句改，直到满意；
- 掷骰子，随机出一个。

做好了存进像素动画列表，拿去当开机动画或 dsh 的背景。

已经定的事：

| | |
|---|---|
| 放在哪儿 | 只放在 dsh 里（「她」→ 外观 → 像素动画）；项目网页上不放 |
| 对话 | 单开一段，不和「她 · 设计」（改编排、皮肤那段）混在一起；每个草稿一段 |
| 掷骰子 | 纯随机，不能锁住某一项。骰子有 6 个面，一面一个方向，各面出现的机会不一样；每次结果都不一样 |
| 顺序 | ① 工坊页、基础设置、调色轮、版本、掷骰子 ② 接上 AI ③ 像素精灵 `g.sprite()` ④ 图片转精灵 |

## 1. 页面

入口：
- 像素动画页上的「做一个」：打开一个空草稿。
- 自己的动画上的「接着改」：拿它当第一版。
- 内置动画上的「照着做一个」：复制一份当第一版，原来那个不动。

```
┌──────────────────────────────┬──────────────────────┐
│                              │  对话                 │
│        预览（一直在播）        │  你：做一只小鲸鱼……    │
│                              │  AI：做好了，v3 ✓      │
│  v1 v2 [v3] v4   ↶ 退回       │                      │
├──────────────────────────────┤                      │
│ 🎲 掷骰子                     │                      │
│ 画法  ○圆点 ○方块 ○代码字       │                      │
│ 颜色  (调色轮)  □跟着主题        │                      │
│ 格子  粗 · 中 · 默认 · 细       │                      │
│ 时长  一直循环 / 1–8 秒         │                      │
│ 帧率 · 大小 · 铺满/完整         │  [ 说你想怎么改…  ] ↵  │
├──────────────────────────────┴──────────────────────┤
│ 名字 [________]   保存   设为开机动画   设为背景   导出 .js │
└─────────────────────────────────────────────────────┘
```

手机宽度上从上往下排：预览、对话、设置（设置默认收起）。

### 1.1 设置分两层

| | 外观层 | 动作层 |
|---|---|---|
| 是什么 | 画法、颜色、大小、铺满还是完整显示 | 画什么、怎么动 |
| 存在哪 | 引擎的设置（`PixelLook`），不在代码里 | 代码 |
| 谁来改 | 用户拖一下，马上变 | AI，或掷骰子 |

还有几项写在代码的 `info` 里：格子大小、帧率、时长、单色还是彩色。这几项由引擎直接改 `info` 那一行，不经过 AI，改完重新试跑一遍。格子大小改了，按固定坐标画的动画可能会跑偏，所以页面上会提示"改了格子，画面可能要让 AI 调一下"。掷骰子出来的代码都按 `g.w`、`g.h` 画，不会跑偏。

### 1.2 调色轮

- 一圈色相，加一条亮度。点中间的"跟着主题"，就回到 dsh 主题的颜色（`color: 'theme'`）。
- 单色动画：颜色就是 `look.color`，拖的时候预览马上跟着变。
- 彩色动画：颜色是代码自己给的，调色轮变灰，旁边说明"这是彩色动画，颜色在画面里；想换颜色，跟 AI 说"。

### 1.3 版本

- AI 每改一次、每掷一次，都存成新的一版：v1、v2、v3……点哪一版就回到哪一版，接着从那里改。
- 一个草稿最多留 30 版，再多就丢掉最早的（第一版一直留着）。
- 草稿放在 `<home>/pixel-drafts/<草稿id>/`：每版一个 `v<n>.js`，`draft.json` 里记着名字、外观、当前是哪一版、对话的 id。
- 「保存」：把当前版本复制进 `<home>/pixels/<id>/`，和上传的动画放在一起，不再另做一套存储。保存以后草稿还在，还能接着改，改完再存一次就是更新。

## 2. 🎲 掷骰子

不用 AI，不花钱，不联网。点一下，骰子滚大约 0.8 秒，停在某一面，预览马上开始播。

### 2.1 六个面

一面一个方向。各面出现的机会不一样，可以把它想成一颗灌了铅的骰子：

| 面 | 方向 | 机会 | 配方 |
|---|---|---|---|
| 🌊 | 水 | 22% | 波浪、雨、涟漪、气泡上升 |
| 🌌 | 天空 | 20% | 星空闪烁、流星、极光、云 |
| 🔥 | 光与火 | 18% | 火焰、烟花、萤火虫、闪电 |
| 🔷 | 几何 | 16% | 万花筒、李萨如曲线、旋转多边形、螺旋 |
| 🌀 | 流动 | 14% | 数字雨、噪声流场、粒子群、隧道 |
| 🌱 | 生长 | 10% | 生命游戏、分形树、雪花结晶、藤蔓 |

机会是我们定的默认值，以后按大家喜欢哪些再调。用户不能调，也不能锁住某一项，这就是"纯随机"。

### 2.2 掷一次随机哪些东西

1. 掷出哪一面（按上面的机会）。
2. 这一面里用哪个配方（机会相同）。
3. 配方自己的参数：数量、速度、密度、对称几份、方向、粗细……每个参数都有一个"好看的范围"，只在范围里取，保证出来的东西不难看。
4. 外观也随机：
   - 画法：圆点 45%、方块 35%、代码字 20%。
   - 颜色：在色相环上随机取，饱和度和亮度只在好看的范围里取；有 10% 的机会是"跟着主题"。
   - 格子：中、默认、细。
   - 时长：一半一直循环，一半 3–8 秒一遍。
5. 有 15% 的机会**混搭**：另掷一个方向，把它叠在底下，调暗一些（比如烟花底下叠一层星空）。
6. 一个随机的种子写进代码。所以参数相同，画面也不一样。

### 2.3 保证每次都不一样

- 记住最近 50 次掷出的"指纹"：哪个配方，参数分在哪一档。太像就悄悄重掷，最多重掷 5 次。
- 连着两次不出同一个配方。

### 2.4 掷出来的是什么

一份普通的像素动画 `.js`，格式和上传的完全一样，开头有一行注释说明它是哪一面、哪个配方。所以掷出来以后：
- 满意，直接保存；
- 接着跟 AI 说"在这上面加一只鲸鱼"；
- 再掷一次，换成新的一版（旧的还在版本里）。

自动起个名字：颜色加配方，比如"蓝色烟花""青色万花筒"，用户可以改。

### 2.5 代码放哪

- `src/core/pixel-dice.ts`（不碰页面、不碰文件）：六个面、配方、参数范围，以及"按种子生成一份代码"。
- 每个配方是一段代码模版，随机出来的参数作为常量填进去。
- 测试：
  - 每个配方取参数范围的最小值、最大值和中间值，都要能通过格式检查、画得出东西、每帧在时间限制以内；
  - 掷 1000 次，不出现两份一样的代码；
  - 六个面出现的比例接近设定的机会。

## 3. 和 AI 一起改

### 3.1 对话

- 每个草稿单开一段对话，放在她的工作区里，标题"做像素动画：<名字>"。不和「她 · 设计」混：代码很长，混在一起会让 AI 分心，也会把那段对话撑满。
- 对话**就在工坊页的右边**，不跳去 dsh 的对话页。做法和她的对话小条一样：插件在会话里听 `agent/assistant-stream`，把回答一段段推给页面。页面上另有一个"在 dsh 里打开这段对话"的链接，备用。
- 用户在 dsh 里给她配的是哪个模型，这里就用哪个。我们不出钱，key 不离开本机。
- 这段对话只给像素动画的工具，dsh 自己的工具（跑代码、读文件）都关掉。这和「她 · 设计」现在的做法一样。

### 3.2 AI 的工具

| 工具 | 做什么 |
|---|---|
| `pixel_read` | 读当前版本：代码、`info`、外观 |
| `pixel_write(code, note)` | 交一份新代码。引擎检查、试跑，通过了就存成新的一版，预览开始播；把结果告诉 AI |
| `pixel_look(…)` | 改外观（画法、颜色）。只在用户明确说"换成方块"这种话时用 |

给 AI 的说明，就用现成的「给大模型的说明」（`pixelSpec()`），再加几条：
- 先读再改，只改用户说的地方；
- 交了以后看试跑的结果，失败了自己改，一句话里最多自己改 3 次；
- 改完用一句话说改了什么。

### 3.3 试跑在哪儿跑

规矩不变：**动画代码不在插件进程里跑，只在页面的沙盒里跑**（见 `src/dsh/pixels.ts` 开头）。

所以 `pixel_write` 的流程是：插件把代码转给开着的工坊页 → 页面在沙盒里试跑（现成的 `probePixel`）→ 把结果送回插件 → 插件交给 AI。用户正在这页上和 AI 说话，页面一定开着。万一 10 秒没回音，工具就告诉 AI"页面没开，没法试跑"，AI 再转告用户。

### 3.4 让 AI "看见"自己画的

AI 看不到画面，这是做得像不像的关键。试跑以后，把开头、中间、结尾三帧缩成字符画交给 AI，比如 48 × 27，按亮度用 ` .:+#` 五档：

```
第 60 帧（2.5 秒）
................................................
..................######........................
................##########......................
...............###..####..#.....................
```

一起交回去的还有：
- 有没有报错、错在第几行；
- 每帧多少毫秒；
- 画到了多少格，画面是不是太空、太满；
- 东西有没有跑出格子。

AI 就能自己发现"尾巴歪了""身子太小""全挤在左边"。字符画也是文字，DeepSeek 能读，花不了多少钱。

### 3.5 一轮是什么样

1. 用户："做一只小鲸鱼，从左边游到右边，吐泡泡。"
2. AI 写代码，调 `pixel_write`。试跑报错：第 12 行。AI 自己改，再交。这次通过了，看了字符画，发现鲸鱼太小，再改一次。v2 开始播。
3. AI："做好了：一只小鲸鱼从左游到右，一路吐泡泡。觉得哪里不对就告诉我。"
4. 用户："泡泡多一点，鲸鱼大一点。"
5. AI 先 `pixel_read`，只改那两处，交上去，v3 开始播。
6. 用户拖一下调色轮换成粉色。这一步不经过 AI。
7. 保存，设为开机动画。

## 4. 像素精灵 `g.sprite()`

用圆和线拼出一个认得出来的角色，大模型很难画像。像素画本来就是一格一格点出来的，所以给 `g` 加一个画像素图的办法：

```js
const WHALE = [
  '....1111....',
  '..11222211..',
  '.1223333221.',
  '122333333221',
]
g.sprite(x, y, WHALE, { flip: false, scale: 1 })
```

- 单色动画：`1`–`9` 是亮度（`9` 最亮），`.` 和空格是透明。
- 彩色动画：再给一张调色板，比如 `{ a: '#ffcc00', b: '#e02020' }`，一个字母一种颜色。
- 动起来靠移动、翻转、缩放，以及换帧：多画几张，比如眨眼的一张、张嘴的一张，轮着用。
- 文件格式还是 `dsh-her-pixel@1`，只是 `g` 多了一个函数，旧文件照样能用。用了 `g.sprite` 的文件放到旧版本的 dsh-her 里会报错，错误提示改成"这个动画要 dsh-her 0.10 或更新"。
- 「给大模型的说明」里加上 `g.sprite`，并告诉 AI：画角色、物件时先用像素图画，再让它动。

## 5. 图片转精灵

用户在工坊里上传一张图，引擎把它变成像素精灵，写进代码，AI 只负责让它动。比如"把我的鲸鱼娘头像变成像素小人，跳一跳"。

- 全在页面里用 canvas 做，图片不上传、不保存，只有转出来的字符串进代码。
- 步骤：
  1. 去掉背景：透明图直接用；纯色底的，用素材库现成的"抠掉背景"。
  2. 裁到主体。
  3. 缩到 24–64 格高，用户拖一下就能选。
  4. 单色按亮度分成 9 档；彩色合并成最多 16 种颜色。
- 转好以后自动在对话里说一句"这是转好的像素图（32 × 40），想让它怎么动？"

## 第 ① 步的实际做法

2026-11-21。和上面不一样、或者上面没说的地方：

- **每一版记着自己的外观**：掷出来的一版带着它自己的画法和颜色；在某一版上拖调色轮，改的是这一版的外观。点回哪一版，画面和外观一起回来。
- **名字**：掷骰子自动起的名字（"蓝色烟花"），再掷会跟着换；你自己改过名字，就不再自动换。
- **格子、帧率、时长**：在文件末尾加一行 `;Object.assign(info, {…}) // 工坊里的设置`，再改就替换这一行。任何写法的 `info` 都管用，AI 以后读代码也看得懂。
- **保存**：先在沙盒里试跑一遍，拿到缩略图和每帧耗时，再存进 `<home>/pixels/`。第一次是新的，以后再存是更新同一个（名字可以变，id 不变）。「接着改」自己的动画，存的时候也是更新它；「照着做一个」自带的，存成新的。
- **设为开机动画 / 设为 dsh 背景**：先保存，再换上，用的是工坊里的外观。
- **空草稿**：点了「做一个」但没掷过的草稿，不出现在「没做完的」里，过一分钟自动清掉。
- **最近 50 次的指纹**存在这个浏览器的本地存储里；读不到就只防"连着两次同一个配方"。
- 代码：`src/core/pixel-dice.ts`（骰子）、`src/core/pixel-workshop.ts`（改 info 的那一行）、`src/dsh/pixel-drafts.ts`（草稿）、`src/client/PixelWorkshop.tsx`（页面和调色轮）。测试：`tests/pixel-dice.test.ts`、`tests/pixel-workshop.test.ts`。

## 第 ② 步的实际做法

2026-11-21。§8 里没定的那件，验证过了：工坊这段对话的回答能一段段拿到，所以对话就在工坊页右边，没有退到 dsh 的对话页。

- **页面怎么知道新消息**：页面每半秒问一次（AI 没在做事时两秒一次），拿到整段对话。插件这边不推送。
- **试跑**：AI 交代码时，插件把代码挂在这段对话上；页面下一次来问时看到了，就在沙盒里试跑，把结果送回来。8 秒内页面没来问过，就当页面没开着，直接告诉 AI；送去以后 25 秒没有结果，也一样。
- **字符画**：在一遍的 20%、50%、90% 三处各取一帧，缩成 48 列（行数按格子的比例），亮度分五档 ` .:+#`；还附上画到的格子占多少、画面在左右上下的什么范围。代码在 `src/core/pixel-sketch.ts`。
- **一次回答最多交 4 次**，第 5 次直接让 AI 停下来问用户。
- **对话记在草稿里**（`chat.json`：dsh 会话的 id 和说过的话，最多 200 条），重新打开草稿还在；插件重启后接着用同一个 dsh 会话。
- **提示词**里加了一条：画人物、动物、物件时，先用一组字符串画出像素图再一格一格画，比用圆和线拼更像（为第 ③ 步的 `g.sprite` 铺路）。
- AI 想了多久，页面上显示"AI 正在做……23 秒"：真模型第一次写代码要想一分多钟。
- 用真模型试过两轮（"一只小鲸鱼从左边游到右边，一路吐泡泡"，再"鲸鱼再大一倍，游得慢一点，眼睛要看得出来"）：第二轮 AI 先读了代码，只改了说的地方，看了字符画才回话。
- 代码：`src/dsh/pixel-chat.ts`（会话、工具、试跑转交）、`src/core/pixel-sketch.ts`，页面在 `src/client/PixelWorkshop.tsx`。测试：`tests/pixel-chat.test.ts`。

## 第 ③ 步的实际做法

2026-11-21。`g.sprite(x, y, 图, 选项)`，和 §4 不一样或者多出来的地方：

- 图可以是一组字符串，也可以是一整段带换行的字符串。
- `'.'` 和空格不画；`'1'`–`'9'` 是亮度，`'0'` 是全暗（会盖住下面画过的）；`'#'` 和没在调色板里的字母都按最亮画。
- 选项多了 `flipY`（上下翻转）、`center`（x、y 是图的中心）和 `a`（透明度）。`scale` 可以是小数，限制在 0.25–16 之间。
- 返回画了多宽。图最多 400 × 400 个字符。
- 「给大模型的说明」里加了 g.sprite 的用法和一小段「画角色、动物、物件」，带一个能跑的例子（一条小鱼游过去再翻身游回来），测试会把这个例子真的跑一遍。
- 旧版本：文件格式还是 `dsh-her-pixel@1`。说明里写了"用了它的动画，放到很旧的 dsh-her 里会播不了"，没有写具体版本号。桌面程序的播放器是打桌面程序时一起打进去的；现在发布的桌面程序（0.8.4）还没有像素播放器，下一次打桌面程序时自然就带上了。
- 用真模型试过："一只像素小猫坐在地上，尾巴慢慢摇，隔一会儿眨一下眼"，AI 用 g.sprite 画了睁眼、半闭、闭眼三张图轮着换，尾巴用圆点画。一次就通过，看得出是猫。

## 第 ④ 步的实际做法

2026-11-21。工坊里骰子旁边的「🖼 用图片做」：

- 选一张图（PNG、JPG、WebP、GIF、BMP），在页面里先缩到长边最多 512 像素再转。图片不上传、不保存，放进草稿的只有转好的字符。
- **去背景**：没有用素材库的"抠掉背景"（那个在插件里用 ffmpeg 做，要把图传过去）。改成在页面里做：边上大多数是同一种颜色（至少六成），就从边上往里，把连着的这种颜色去掉；画面中间同样的颜色不动。图本来就是透明底的，直接用。边上颜色杂的，不去，界面上会说"背景不是纯色，没去掉"。
- 裁到剩下的东西，缩成 24 / 32 / 40 / 48 / 64 格高，最宽 96 格。每一格取它盖住的那片像素的平均。
- **单色**：按亮度分成 '1'–'9'，最暗的算 1、最亮的算 9，拉满。之后还能换画法、调颜色。**彩色**：用中位切分挑出最多 16 种颜色，一种颜色一个字母（a–p）。彩色动画只能画成方块，所以放进草稿时画法自动换成方块。
- 放进草稿是新的一版：图放在中间、占画面八成，轻轻上下浮动。对话里出现一句"🖼 图片转成了像素图（18 × 64 格），放进了 v1……想让它怎么动，在下面说"。这句是页面加的，不发给 AI。草稿名字还是默认的话，就改成图片的文件名。
- 文件开头有两行注释，AI 的提示词里也加了第 8 条：PICTURE 是用户的图，原样保留，要眨眼、张嘴就复制一份只改那几格。
- 试过：拿仓库里那张绿幕全身照转成 18 × 64、16 色，绿幕去干净了。再跟 AI 说"让她原地轻轻左右摇摆，像在跟着音乐晃"，AI 没动 PICTURE，一行一行错开画出摇摆，脚底不动，越往上晃得越多。
